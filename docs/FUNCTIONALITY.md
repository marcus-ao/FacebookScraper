# 功能基线 · 按流水线阶段

**业务决定版本：2026-09-12。** 本文件是功能语义的权威来源。代码状态只是为了避免把未来设计写成现状；逐项实施清单与证据栏在 [OPTIMIAZATION.md](OPTIMIAZATION.md)。

## 0. 阅读规则

状态只有五种：`代码未完成`、`离线通过`、`待真实联调`、`真实通过`、`明确延期`。`离线通过` 只表示规划阶段的 47 个离线脚本或前端构建覆盖了对应契约；它不替代企业账号、浏览器、模型或远端存储的真实证据。

当前 worktree 没有运行数据。原工作区的 Facebook 47 篇和 `in_neakasa.tech` 1020 篇是历史归档，不能证明新目标 `neakasa.global` 已完成回填或联调。

### 0.1 固定前提

| 前提 | 决定 |
|---|---|
| 目标 | Facebook `neakasaofficial`；Instagram `neakasa.global` |
| 旧目标 | `in_neakasa.tech` 冻结，只读 |
| 路由 | FB/IG 独立车道；来源平台就是唯一发布渠道；不跨平台合并 |
| 合作帖 | `.global` 时间线上的合作帖全部抓取，不限合作方 |
| 审校人 | 1 人，上海 08:00–19:00，中文桌面界面 |
| 时间 | 人选柏林时刻；同渠道前后 90 分钟冲突则拒绝并建议 |
| 人工优先 | 人工文案、人工图片和人工决定永不被机器覆盖 |
| 付费 | 统一预算 + 来源许可；不确定请求先核账再重放 |
| 图片优化 | 每张图最多受理三次 |
| 挂起 | 默认三个上海工作日 |
| actor | 本轮字段固定为 `null`；身份与权限延期 |
| 云盘 | 本地到飞书的单向镜像；版本追加；冻结内容补送旧版 |
| 发布语义 | `scheduled` = 排期回读确认，不等于已经公开发布 |

### 0.2 典型一天

离岗时发现的新帖可以完成抓取和准备，但不在离岗窗打扰运营。下一在岗窗开始时，飞书把仍然有效的待审内容合并送达。运营进入审校台，修改正文/标签/链接，核对图片，选择柏林时刻。系统先检查同渠道 90 分钟占用，再展示冻结后的最终提交快照。获得确认后，发布浏览器只选择来源渠道，提交并回读；回读成立才写 `scheduled` 和发送回执。

这是目标流程。凡涉及真实模型、飞书、云盘或 Business Suite 的部分，在完成 [OPTIMIAZATION.md](OPTIMIAZATION.md) 对应证据前都不算真实通过。

## 1. 阶段一：监测有没有新帖

### F1-1 独立目标与合作帖

**决定：** FB 和 IG 分开探测、分开归档。IG 目标是 `neakasa.global`；`parse.on_timeline_of()` 判定时间线归属，所有 `.global` 合作帖都进入归档。`in_neakasa.tech` 不再运行。

**状态：离线通过，待真实联调。** 需要在真实 `.global` 页面确认首屏、合作帖和增量状态；当前 worktree 没有相应 archive/state。

### F1-2 按在岗窗分层调度

**决定：** 上海 08:00–19:00 使用较短间隔，离岗窗使用较长间隔，触发时刻带随机抖动。频率来自配置，但任何配置都受 C7 请求/会话/失败预算约束；系统不得自行提频。

**状态：离线通过，待真实联调。** 常驻 `pipeline.scheduler` 已有离线计划逻辑；当前没有完成的新调度器一键安装命令，`tools.schedule install` 仍是旧每日任务。

### F1-3 07:00 兜底对账

**决定：** 每个平台每天在 07:00 上海时刻附近做一次带抖动的有限深扫，目标是在 08:00 前暴露遗漏。错过截止线时保留下次计划并显式报错，不在启动后密集补跑。

**状态：离线通过，待真实联调。** 不允许自动滚全部历史，也不绕过深度和会话预算。

### F1-4 三个浏览器角色

**决定：** 回填号/profile/9222、发布号/profile/9223、探测号/profile/9224 互相隔离。所有登录由人完成；代码只附着现有会话。

**状态：离线通过，待真实会话核验。** 旧“两浏览器”口径已废止。

### F1-5 跳过与故障可见

**决定：** 每轮分别报告新增、纯视频、图文混合、无媒体、无正文、第三方许可阻塞、失败和未读坏数据。“无新帖”不能掩盖“全被跳过”。

**状态：离线通过；真实日报仍受 F4-3 约束。**

### F1 验收

- 两个平台的计划、锁和状态彼此独立；目标切换不会继承旧 `.tech` 游标。
- `.global` 合作帖不会因作者不同被丢弃。
- 注入时钟能证明在岗/离岗/07:00/错过窗口行为。
- 真实探测证明 9224 会话有效，且不会触发自动登录、自动历史滚动或额外重试。

## 2. 阶段二：抓取与存储

### F2-1 一个本地真相，多个派生视图

**决定：** `post.json` 和原图是来源真相；人工文案、审校账本、付费账本和发布账本分别是不可由索引覆盖的真相源。manifest、SQLite、HTML、Planner 缓存和云盘都是派生物。

**状态：离线通过。** 当前恢复相关代码仍有未完成修改，真实旧数据接续后再更新状态。

### F2-2 可追溯布局与冻结快照

**决定：** 每帖目录以日期、时分、ID 可读命名；原图只读。任何发布、镜像或补送使用冻结内容快照，不能在异步执行时重新读取“当前文件”并悄悄改变内容。

**状态：离线通过；所有发布入口的快照投影仍代码未完成。** 当前批准路径有快照目录，但 CLI 等入口尚未证明共用同一投影。

### F2-3 分类标签

**决定：** 来源标签自动预填，人工可改；分类标签与发布 hashtags 分开。修改必须带来源版本和当前 revision，冲突时拒绝覆盖。

**状态：离线通过。**

### F2-4 飞书云盘单向镜像

**决定：** 本地到云盘，永不反向读。每个版本使用新目录；已存在版本不覆盖。只有保存过的冻结内容能补送历史缺口；`state/` 中需要恢复的账本一并镜像，但云盘副本仍不能反向参与日常决策。

**状态：离线通过，待真实联调。** 需要企业权限、目标目录和真实上传回执，且要证明当前版本与补送版本不会串内容。

### F2-5 源帖变更

**决定：** 新来源哈希使机器派生物过期。人工版保留并标红复核；已排期内容只告警，不自动修改远端。旧版本保留，不覆盖。

**状态：离线通过。**

### F2 验收

- 从 posts 重建 manifest/SQLite 不改变人工、付费或发布真相。
- 人工稿/图在重译、重建、镜像和刷新后保持优先。
- 损坏或缺失的不可重建账本会阻止继续，而不是产生空状态。
- 云盘真实目录证明单向、追加版本和冻结补送。

## 3. 阶段三：翻译、标签与链接

### F3-1 三块本地化编辑

**决定：** 正文、hashtags、链接分别编辑和验证。正文不能混入裸 URL 或发布标签；品牌/型号等受保护标签原样保留。

**状态：离线通过。**

### F3-2 渠道链接语义

**决定：** Facebook 展示原链接和德语落地页映射；Instagram 使用配置中的 bio 目标和可审校引导语。两渠道不共享草稿。

**状态：离线通过，待真实内容联调。**

### F3-3 人工优化循环

**决定：** 单篇指令只作用于该篇，模板提示词不被修改。正文优化和图片优化分别记账；每张图最多受理三次。挂起、刷新或服务重启不得丢失任务终态。

**状态：离线通过；孤儿模型任务恢复代码未完成。** 待处理 `pending/running` 任务在进程退出后的回收、费用核对和安全重试。

### F3-4 确定性检查与真实风险预扫描

**决定：** 金额、受保护标签、@提及、数字/单位等走本地确定性检查；俚语/双关、歧义、美国限定语境才走风险模型。两类提示在 UI 中分开。

**状态：确定性检查离线通过；风险预扫描代码未完成。** `web/api/fixtures/risks.json` 是手写演示数据，不得显示为当前任务的真实风险。

### F3-5 德语 hashtag 推荐

**决定：** 推荐来自真实采样的德语信号，记录来源、时间和原始值；排序解释可见。采样不可用时降级为语义人工选择，不阻塞发布，也不伪造热度。

**状态：排序/存储离线通过；真实 samplers 代码未完成。**

### F3-6 付费边界

**决定：** 抓取全部符合范围的内容；进入付费步骤前检查来源许可。预算是跨入口统一的日/月账本。远端结果不确定时记为不确定并先核账。

**状态：离线通过，待真实模型联调。**

### F3 验收

- 一篇内容的 FB/IG 草稿不会合并或互相覆盖。
- 人工保存后重跑报告不会恢复机器版本。
- 孤儿任务能分成“未提交、已计费待回收、需人工核账”，不会永远运行或重复收费。
- 风险结果包含真实来源/模型/内容哈希；夹具只在明确演示模式出现。
- 至少一个真实采样源成功；全部源失败时 UI 清楚显示降级。

## 4. 阶段四：飞书推送

### F4-1 企业应用通道

**决定：** 使用企业飞书自建应用和明确收件人。凭据只在本机，日志与仓库不出现密钥。

**状态：离线通过，待真实联调。**

### F4-2 当前内容卡片

**决定：** 待审、排期成功、提交失败、系统故障和积压摘要使用不同消息。发送前必须重新解析当前任务状态、当前文案和当前预览；已离开待审队列的旧事件不得继续发送旧内容。

**状态：代码未完成。** 当前消息路径尚未完整证明“当前内容”投影。

### F4-3 去重、静默时段与日报

**决定：** 每个业务事件有稳定幂等键；确定已送达的不重复，结果不确定的请求不盲重放。在岗即时；离岗积压到下一 08:00 合并。每天产生一次状态摘要，区分正常空轮次、分类跳过、积压、成功、失败和不确定投递。

**状态：投递账本离线通过；业务去重和每日摘要代码未完成。** 不把本机自发消息当外部心跳。

### F4-4 卡片动作

**决定：** 卡片至少包含平台、账号、来源时刻、当前文案摘要、风险/硬闸、当前图片预览和审校台链接。卡片可引导审校，不能绕过网页中的版本检查与提交确认。

**状态：待真实联调。**

### F4 验收

- 编辑后排队、离岗积压和重启场景都发送当前版本。
- 同一事件重复处理只产生一个确定投递；不确定远端请求停下来核对。
- 日报在“零新帖”和“全部跳过”时内容不同。
- 企业环境实际收到卡片、图片和链接，并验证权限最小化。

## 5. 阶段五：审校、排期与月历

### F5-1 同渠道 90 分钟冲突

**决定：** 目标时刻前后 90 分钟内，同渠道已有任意 Planner 卡片即冲突。人工选择的时刻直接拒绝并给候选；不自动顺延。Facebook 占用不阻塞 Instagram，反之亦然。

**状态：离线通过，待单渠道 Planner 真实证据。**

### F5-2 柏林输入与 Business Suite 可见范围

**决定：** 运营输入柏林时刻；系统按 UI 时区换算并以 Planner 当前可见范围为边界。2026-09-01 的“当月最后一天”是当时 UI 事实；跨月时必须重新读取和适配，不把固定同月限制写成永久业务规则。

**状态：当前月计算离线通过；跨月适配代码未完成。**

### F5-3 七态审校

**决定：** `pending_review → edited/snoozed/approved`，提交回读成功到 `scheduled`，失败回到 `pending_review`；`skipped` 和 `handed_off` 是不同终态。挂起到期或源文变化可回待审。

**状态：离线通过。** 所有事件 `actor: null`。

### F5-4 审校账本完整性

**决定：** `review_items.jsonl` 是追加式真相源。空白行可忽略；任何非空坏 JSON、缺字段、非法状态、坏 revision 或坏时间都要显式失败并保留现场。

**状态：代码未完成。** 当前读取会静默跳过坏行，可能把旧状态当成最新状态。

### F5-5 当前队列、90 天历史与月历

**决定：** 默认列表显示当前待办；历史视图只展示最近 90 天并可按状态/渠道筛选，底层数据不裁剪。月历显示缓存时间、覆盖范围和过期状态；手动刷新与提交共用发布锁。

**状态：队列/月历离线通过；90 天历史 UI 代码未完成；Planner 待真实联调。**

### F5-6 修改、资源下载与人工接管

**决定：** 不发必须填理由。人工接管先生成完整 ZIP，再记录 `handed_off`；可回填公开链接。已接管项目可重下同一冻结内容，不改变终态。

**状态：离线通过。**

### F5-7 所有发布入口的快照

**决定：** 审校台批准、CLI 和未来入口都从同一不可变提交快照派生，快照包含来源哈希、当前人工优先文案、图片内容哈希、单一渠道、目标账号和时刻。提交后 receipt 绑定该快照。

**状态：代码未完成。** 当前批准路径存在快照，尚未证明所有入口覆盖和投影一致。

### F5-8 单渠道证据与回读

**决定：** 来源渠道是唯一目标。提交前显式选择一个渠道并核对目标账号；提交后分别回读对应渠道和 remote ID。不能沿用 composer 默认双选，不能只在 journal 写单渠道字段。

**状态：代码未完成且待新 probe。** 当前代码会在打开浏览器前失败闭合；2026-09-01 dump 没有渠道勾选证据。

### F5-9 发布锁与不确定提交

**决定：** Planner 刷新、提交前检查和真实提交共用跨进程发布锁。点击前先写 durable intent；点击后崩溃或结果不确定时不自动重试。`scheduled` 只在成功回读后写。

**状态：离线通过，待真实联调。**

### F5 验收

- 损坏审校行使 API/CLI 明确失败并指出文件，不继续展示推导状态。
- 历史 UI 只查询最近 90 天，归档和账本内容不被删改。
- 月末到次月的可选范围来自新读取的 Planner 覆盖，而非硬编码同月。
- 新 probe 记录 FB-only 和 IG-only 的渠道操作、账号、时间控件、成功回读与 remote ID。
- 每个真实提交 receipt 可回到唯一快照；改变当前文件不能改变已经冻结的提交。
