# 审校台设计系统（草案）

**成文日期：2026-09-13。状态：草案，待批准。**

> ⚠️ 不要和 [`web/DESIGN.md`](../../web/DESIGN.md) 搞混。那一份是**接口与业务契约的真相源**（状态模型、字段、验收），本文件只管**视觉与交互口径**。两者冲突时，`web/DESIGN.md` 赢。

这份文件写的是我们这个审校台，不是 Ant Design 的文档摘抄。每一条口径后面都跟一句"为什么是这个值"，依据来自 [UI_AUDIT.md](UI_AUDIT.md) 量出来的现状和这个产品自己的业务约束。没有依据的数值我不写，宁可留一句"Stage B 定"。

## 1. 产品性格

### 1.1 她是谁，她在干什么

一名上海运营，非技术背景，上海时间 08:00–19:00 在岗，用 Windows 桌面（约 99%），中文界面。她一天的动作是：**打开列表 → 挑一篇 → 读英文 → 读德语 → 逐个看标记 → 改文案 → 核对图片 → 选一个柏林时刻 → 通过 → 下一篇。** 一天十几到几十次。

这决定了性格里最重要的一条：**这是一个她用六个月之后仍然要每天打开的工具。** 所以任何"第一次看很惊艳、第三十次看很烦"的东西都是错的——入场动画、装饰卡片、常驻的解释文字、每篇都出现的黄色警告，全部属于这一类。

### 1.2 六个词

| 性格 | 在这个产品里具体意味着 |
|---|---|
| **平静** | 界面在"没有问题"的时候应该是安静的。没有硬闸告警不需要一行绿字宣告；没扫过风险不需要一块黄面板。信号只在异常时出现，这样它才还是信号 |
| **现代** | 现代感来自克制：统一的控件、稳定的节奏、清楚的层级。不来自渐变、毛玻璃、大阴影 |
| **精确** | 金额、尺码、柏林时刻、图片张数——错一个有真实业务后果。数字用等宽数位（`font-variant-numeric: tabular-nums`），时刻永远带时区词，不确定的值显示为"未知"而不是空 |
| **低噪** | 一屏里同时出现的饱和色块不超过两处；`Tag` 不超过 8 个；解释性文字为 0 |
| **面向操作** | 密度优先于呼吸感。1366×768 下列表首屏 ≥12 条是硬指标（现状 4 条） |
| **桌面优先** | 不为手机牺牲桌面密度。窄屏只保证不崩 |

### 1.3 避免清单

营销站审美、渐变、过度动画、毛玻璃、装饰性卡片、多层阴影、通用 AI 紫、不必要的边框、过大的组件、降低信息效率的空白、常驻的解释性文案。

其中"通用 AI 紫"值得点一句：现有主色是 `#4f46e5`（indigo-600），它正好落在那个区间里。提纲说不需要保留任何品牌色，所以第 5 节换掉它。

## 2. 口径的单一来源

```
app/theme.ts  ──(ConfigProvider theme.token)──▶  antd 组件
     │
     └──(生成 / cssVar)──▶  styles/tokens.css  ──▶  *.module.css
```

**颜色、间距、字号、圆角的字面值只允许出现在 `theme.ts` 一个文件里。** CSS Modules 只引用语义变量。

现状的反面教材：`--space-1..6` 定在 `styles.css`，但 `ApprovalPanel.vue` 写 `padding: 18px`、`RefinementPanel.vue` 写 `padding: 18px`、`HashtagEditor.vue` 写 `padding: 18px`、`CalendarPanel.vue` 写 `padding: 20px`、`SettingsPanel.vue` 写 `padding: 24px`——五个区块五个内边距，都不在刻度上。

`theme.cssVar` 在 antd 6 的可用性是 [UI_ARCHITECTURE_PROPOSAL.md §0](UI_ARCHITECTURE_PROPOSAL.md) 标的待核项；拿不到就从同一份 TS 常量生成两边，结论不变。

## 3. 排版

### 3.1 层级

七级，覆盖全部现有用法。**同级必须同字号**——现状同为区段标题的 `h3` 有 12/13/14px 三种（[UI_AUDIT.md P1-4](UI_AUDIT.md)），这是这一节存在的全部理由。

| 语义 | 字号 / 字重 / 行高 | 用在哪 | 为什么 |
|---|---|---|---|
| **页面标题** | 20 / 600 / 1.4 | 工作区头的"审校队列""历史归档" | 20px 是 1366 宽度下不显臃肿的上限；现状 `h2` 已有 18–20px，沿用 |
| **区段标题** | 14 / 600 / 1.4 | 正文对照、图片、标签与链接、决策、五个阶段卡 | 与正文同号、只靠字重区分。内网工具的区段标题不需要比内容大——它只需要可定位 |
| **子区段标题** | 13 / 600 / 1.4 | 产品分类、处理记录、栏头（英文原文 / 德语译文） | 比区段低一档，不另开字号 |
| **条目标题** | 14 / 400 / 1.5 | 列表行的德语摘要 | 它是列表的"标题"，但内容是散文，加粗会让整列变黑 |
| **正文** | 14 / 400 / 1.5 | 详情正文对照的两栏 | ⚠️ 例外见 §3.2 |
| **次要内容** | 13 / 400 / 1.5 | 说明、`Tooltip` 内容、决策卡的值 | — |
| **元信息** | 12 / 400 / 1.4 | 时刻、计数、平台、账号、图片张数 | 12px 是中文在 Windows ClearType 下仍清晰的下限。不能再降——现状已经在 11px 上用过（`.len`、`.calendar-entry summary`），那是不该越的线 |

### 3.2 正文对照是唯一的例外

英德两栏的正文用 **15px / 1.7**，不是 14 / 1.5。

理由：这是她一天里唯一要**逐字读**的地方。中位正文 843 字符、最长 2,838 字符，德语再长 10–20%；1.7 的行高在这种长度上明显更容易不串行。现状 `TextCompare.vue:186-193` 已经是 15px/1.7，这个决定是对的，写进系统。

另外这两栏的字体、行高、内边距、`white-space`、`overflow-wrap`、`letter-spacing` 必须与编辑态的镜像层**逐像素一致**，否则标记会和字错位。这是约束，不是偏好。

### 3.3 字体栈

系统栈，`Segoe UI` 优先，不引外链字体。生产机要求断网可跑，外链字体会挂住首屏。等宽栈 `Cascadia Mono, Consolas` 只用在哈希、请求 ID、模板内容上。

数字一律 `font-variant-numeric: tabular-nums`：时刻列、计数、字符数、金额。理由是列表里这些数要上下对齐着扫。

## 4. 间距

8px 基准，与 antd 的 `sizeUnit: 4 / sizeStep: 4` 兼容。刻度只有六档，**不许出现刻度外的值**：

| token | 值 | 用在哪 |
|---|---|---|
| `space-1` | 4px | 图标与文字之间、`Tag` 内边距 |
| `space-2` | 8px | 行内元素之间、按钮组 |
| `space-3` | 12px | 表单项内部、卡内小分组 |
| `space-4` | 16px | 卡片内边距、区段内的块间距 |
| `space-5` | 24px | 区段之间、页面左右边距 |
| `space-6` | 32px | 大区之间（详情的主工作区与下方折叠区） |

沿用现状的 `--space-1..6`（`styles.css:45-50`），值完全一样。现状的问题不是刻度不对，是**没人遵守**（§2 的五个 padding）。

固定高度：

| 元素 | 高 | 依据 |
|---|---|---|
| 顶栏 | 48px | 现状 67px，删掉副标题后 48 足够 |
| 工作区头（列表） | 96px | 页面标题行 40 + 筛选行 40 + 间距 |
| 吸顶审校头 | 56px | 三段布局的最小可用高，且**不允许折行**（现状 43px 但会折成 80px） |
| 表格行 | 48px | 见 §4.1 |
| 控件（按钮/输入） | 32px | 现状 `.btn { min-height: 32px }`，沿用。工具条与表格内用 28px |

### 4.1 48px 行高是怎么来的

1366×768 下：768 − 48（顶栏）− 96（工作区头）− 40（表头）= 584px 可用。584 / 48 ≈ 12.2 → **12 行**。这是 [UI_AUDIT.md P0-1](UI_AUDIT.md) 定的硬指标。

1920×1080 下：1080 − 48 − 96 − 40 = 896。896 / 48 ≈ 18.7 → **18 行**。

48px 里放得下：40×40 缩略图（上下各 4px）、单行 14px 摘要、12px 元信息（如果需要两行则摘要与元信息同行分列）。所以行内**不能有第二行文字**——现状的四层结构必须列化。

## 5. 颜色

### 5.1 三条规矩

这三条是从现有 `styles.css` 的文件头注释继承下来的，它们是对的，只是没被贯彻：

1. **内容区里只有两种饱和色**：红（确定性检查：这里错了）和黄（语义风险：这里注意看）。混成一种，用几次她两种都不信。
2. **主色只出现在操作控件上，绝不进正文。**
3. **背景一律中性灰，不带任何色相。** 底色带色相会削掉红黄两种标记的区分度。

新增第四条，来自 [UI_AUDIT.md P0-2](UI_AUDIT.md)：

4. **状态色只表达状态，不表达动作。** 红色现在同时是"硬闸告警"、"破坏性按钮"和"错误标记"三件事，于是它什么都不是。动作的层级用形态（填充 / 描边 / 文字）表达。

### 5.2 主色：`#155EEF`（Stage B1 定值）

换掉现有的 `#4f46e5`（indigo-600，落在提纲点名要避免的"通用 AI 紫"区间）。

**最终值 `#155EEF`。** 判据不是"看着顺眼"——每一条都算得出来，算法在 `web/ui-next/src/lib/contrast.ts`，断言在 `src/app/theme.test.ts`：

| 判据 | 实测 | 结论 |
|---|---|---|
| 填充按钮上白字 ≥ 4.5:1 | **5.41:1** | ✅ |
| 与错误红 `#dc2626`（0°）区分 | 色相距 **220°** | ✅ |
| 与风险黄 `#b45309`（26°）区分 | 色相距 **194°** | ✅ |
| 焦点环在白底可见（非文本 ≥ 3:1） | 5.41:1 | ✅ |
| 焦点环在 `#f1f5f9` 上可见 | **4.94:1** | ✅ |
| 不是"通用 AI 紫" | 色相 **220°**（旧主色 244°） | ✅ |

**为什么不是 Stage A 占位的 `#1677ff`**：它对白色只有 **4.10:1**，达不到 4.5:1。这条不是审美偏好——主按钮上的白字是「通过并创建排期」这类不能看错的文案，她一天按几十次。这个具体数字有一条专门的测试守着，免得以后有人"顺手换回一个更亮的蓝"。

配套三档（同样只在 `theme.ts` 里）：

| token | 值 | 用途 |
|---|---|---|
| `primary.base` | `#155EEF` | 填充按钮底、焦点环、选中态 |
| `primary.strong` | `#0F47B8` | hover，以及**浅底上的文字** |
| `primary.deep` | `#0C3A97` | active |
| `primary.soft` | `#E8EFFD` | `Tag`、选中的导航项 |

两条要交代的：

1. **hover / active 往深走，不用 antd 默认的"变浅"。** 变浅会让白字的对比度在 hover 那一刻掉下 4.5；往深走反而升到 8:1 以上。
2. **浅底上的文字用 `strong` 不用 `base`。** 12px 的 `Tag` 不适用大文本豁免，`base` 在 `#E8EFFD` 上只有 4.69:1，余量太小；`strong` 是 6.96:1。

### 5.2.1 红与黄的可读性边界（实测记录）

红与黄沿用旧值（见 §5.4），但要记一笔它们**过不了**什么，免得以后被当成"都 ≥ 4.5"用：

| 组合 | 实测 | 允许的用法 |
|---|---|---|
| `#dc2626` on `#ffffff` | 4.83:1 | ✅ 可以做文字 |
| `#b45309` on `#ffffff` | 5.02:1 | ✅ 可以做文字 |
| `#dc2626` on `#f1f5f9` | **4.41:1** | 只做图标 / 线 / 标记底（非文本 ≥ 3:1） |
| `#dc2626` on `#fee2e2` | **3.95:1** | 同上 |
| `#b45309` on `#fef3c7` | **4.28:1** | 同上 |

所以 `ProblemIndicator` 是**图标 + Tooltip**，不是 12px 的彩色文字；正文标记 `mark.mk-*` 的文字色是继承的 `#0f172a`，不是红色。

### 5.3 中性

沿用现状的中性阶（`styles.css:21-27`），它们是 slate 系但已去色相偏移，可用：

| token | 值 | 用途 |
|---|---|---|
| `bg` | `#f1f5f9` | 页面底 |
| `surface` | `#ffffff` | 卡片、表格行 |
| `surface-sunken` | `#f8fafc` | 次级区域（栏头、表头、只读区） |
| `fg` | `#0f172a` | 正文 |
| `fg-muted` | `#475569` | 次要内容、元信息 |
| `border` | `#e2e8f0` | 分隔线、卡边 |
| `border-strong` | `#cbd5e1` | 输入框边、按钮边 |

### 5.4 状态色

| 语义 | 前景 | 浅底 | 用在哪 | 强度约束 |
|---|---|---|---|---|
| **错误 / 硬闸** | `#dc2626` | `#fee2e2` | 硬闸告警、`error` 标记、`danger` 按钮、请求失败 | 一屏内浅底块不超过 1 处 |
| **风险 / 注意** | `#b45309` | `#fef3c7` | `risk` 标记、源文已变、排期冲突、缺德语图 | 同上 |
| **成功** | `#047857` | `#d1fae5` | 已排期、人工版、"都看过了" | **只作为状态标记，不作为 `Alert`**（见 §11） |
| **信息** | 主色 | 主色浅底 | 只读提示、系统状态 | 极少用 |

红与黄的具体十六进制沿用现状——它们已经在这个产品的真实正文（带大量 emoji 的英德文案）上被看过，换值没有收益。

### 5.5 绝不只靠颜色

任何状态必须同时有**图标或文字**。三个理由：

1. 色觉障碍；
2. 红与黄在 12px 的小面积上区分度有限；
3. 现状的实证——`.row.done` 与 `.row.waiting` 用同一个灰底，于是"已处理完"和"还没准备好"在视觉上不可区分（[UI_AUDIT.md §6](UI_AUDIT.md)）。

## 6. 表面与卡片

### 6.1 四层，够了

| 层 | 什么时候用 |
|---|---|
| **页面底**（`bg`，无边框） | 默认。区段之间用 24px 间距分开，**不用边框** |
| **分组区段**（无底色，只有标题 + 间距） | 详情里的大多数分组。这是默认的分组手段 |
| **卡片**（`surface` + 1px `border` + 6px 圆角，**无阴影**） | 只给"可以独立处理的对象"：决策卡、图片对照区、设置表单、运行状态的阶段卡 |
| **浮层**（`surface` + 阴影） | `Modal`、`Drawer`、`Dropdown`、`Popover`、`Tooltip` |

表格行**不是卡片**：用 1px 底分隔线，不用边框 + 圆角 + 阴影 + 8px 间隙。

### 6.2 卡片不是默认容器

现状：列表 17 行 = 17 个卡；历史 30 行 = 30 个卡；详情 12–13 个平级卡（[UI_AUDIT.md P1-3](UI_AUDIT.md)）。边框成了页面上最密的视觉元素，却不表达任何层级。

判据：**问"这块内容是一个可以被单独拿起来处理的东西吗"。** 是 → 卡片。只是"这里有一段内容" → 区段标题 + 间距。

按这个判据，详情页的卡片数从 12–13 降到 3：决策卡、图片对照、（折叠展开后的）优化区。正文对照不是卡片——它是页面的主工作区，占满可用高度，不需要边框把自己框起来。

### 6.3 阴影

只有浮层有阴影。

现状给每个列表行都加了 `box-shadow: 0 1px 2px + 0 1px 3px`，hover 时换成 `0 4px 16px`。17 行 × 2 层阴影 = 34 个阴影在一屏里。删掉。

## 7. 状态表示

八种状态（七态 + `not_ready`），统一用 `Tag`，**字号 12px，无边框，浅底 + 深前景**。

| 状态 | 显示 | 色 | 依据 |
|---|---|---|---|
| `not_ready` | **未就绪** | 中性 | 系统还没准备好，不是她的待办。文案由 [DECISION_LOG.md D1](DECISION_LOG.md) 定为「未就绪」，不再沿用旧 UI 的「待处理」 |
| `pending_review` | 待我审 | 主色浅底 | 这是她的待办 |
| `edited` | 已修改 | 主色浅底 | 同上，进行中 |
| `snoozed` | 已挂起 | 中性 | 她主动放下的 |
| `approved` | 已通过 | 成功浅底 | 正在提交 |
| `scheduled` | 已排期 | 成功浅底 | ⚠️ 只表示排期已被回读确认，**不表示已公开发布**（`web/DESIGN.md §9`）。文案不能写"已发布" |
| `skipped` | 这篇不发 | 中性 + 删除线或锁图标 | 终态。**不用红色**——这是一个正常的业务决定，不是错误 |
| `handed_off` | 已交人工处理 | 中性 | 终态 |

三条纪律：

1. **终态不用红色。** `skipped` 是她有意做的决定，红色会让"正常处理完的帖子"看起来像出了问题。
2. **`scheduled` 的文案不许写成"已发布"。** 这是业务口径，不是措辞偏好。
3. **`not_ready` 与终态必须能区分。** 现状两者同一个灰底，改成：`not_ready` 行正常底色 + 中性 `Tag`；终态行整行降饱和（`fg-muted` 的文字色）。

### 7.1 问题指示（与状态分开）

状态回答"处理到哪一步了"，问题指示回答"这一篇有没有事"。两者是不同的列。

| 指示 | 图标 | 色 | 条件 |
|---|---|---|---|
| 硬闸 | `ExclamationCircleFilled` | 错误 | `hard_alerts.length > 0` |
| 风险 | `WarningFilled` | 风险 | `risk_count > 0` |
| 第三方作者 | `UserOutlined` | 中性 | `author_flag !== null` |
| 无 | 空 | — | 都没有 |

**红色在列表里只出现在这一列。** 定位固定，扫一列就够。具体文案进 `Tooltip`（L2）。

## 8. 按钮层级

| 类型 | 形态 | 用在哪 | 数量约束 |
|---|---|---|---|
| **primary** | 主色填充 | 每个界面的主动作 | **一屏一个**。付费动作不算主动作 |
| **default** | 白底 + `border-strong` 描边 | 次要业务动作（编辑德语、放弃修改、重新读取、刷新月历、生成候选） | 不限，但同一组内不超过 3 个 |
| **text** | 无底无边 | 导航（返回、上一篇/下一篇）、折叠切换、抽屉入口 | 不限 |
| **link** | 主色文字带下划线 | 外链（原帖、落地页检查） | — |
| **danger** | 见下 | 破坏性动作 | 一屏一个，且在菜单里 |

### 8.1 danger 的形态

**danger 只出现在两个位置**：`Dropdown` 的菜单项（`danger: true`），和破坏性 `Modal` 的确认按钮（`danger` 填充）。

**不允许行内的红色描边按钮。** 现状 `.btn-danger` 是红字 + 红边，在列表里出现 17 次（[UI_AUDIT.md P0-2](UI_AUDIT.md))。

现状另一个错：破坏性动作的确认按钮是 `btn-primary`（靛蓝）——"这篇不发"的最终确认长得像"好的，就这样"。改成 `danger`。

### 8.2 disabled 必须给原因

任何 disabled 的按钮都要有 `Tooltip` 说明为什么。

现状最严重的一处：`ApprovalPanel.disabled` 是六个条件的或（`editing || loading || submitting || !eligible || !options?.available || !when`），界面上只有一个灰按钮（[UI_AUDIT.md P2-10](UI_AUDIT.md)）。Tooltip 文案按条件优先级给一句话。

### 8.3 付费动作

付费动作（初翻、文案优化、图片优化）**不是 primary**，但要显眼：`default` 形态 + 按钮文案里带金额（现状"生成图片 · 约 US$0.045" 是对的，保留）+ 旁边一行剩余次数。

理由：她需要知道这个按钮要花钱，但这不是她来这个页面的目的。

## 9. 表单

### 9.1 标签与说明

| 元素 | 口径 |
|---|---|
| 标签 | 顶置（不左置）。中文标签长度差异大，左置会让输入框左边界参差 |
| 必填 | antd 默认的星号，不用"（必填）"文字。现状 `理由（必填）` / `（选填）` 混用 |
| 说明 | **默认不常驻。** 进 `Form.Item` 的 `tooltip` |
| 校验错误 | 就地，`Form.Item` 的 `help` + 红色 |
| 格式提示 | 放 `placeholder`，不另起一行 `<small>` |

### 9.2 什么时候说明可以常驻

只有一条例外：**说明改变了这个字段的业务含义，而不只是解释它怎么用。**

例如"默认排期时间"下面的"修改不会移动已有排期"——这句话防止她以为改了设置就能批量改排期，属于业务含义，可以留（但要缩短）。而"用逗号分隔，例如 10:00, 17:00"属于用法，进 `placeholder`。

⚠️ 设置页的 `editable_help` 是 `config.toml` 的开发者注释，里面有源码路径（[UI_AUDIT.md P0-12](UI_AUDIT.md)）。它**不能删数据**（`web/DESIGN.md §7` 把"注释未丢"与"页面呈现注释"列为两个独立验收项），只能改呈现：移进 `tooltip`，并且只在内容是业务语言时显示。

### 9.3 编辑态要看得见

现状：点"编辑德语"之后，德语栏的边框、底色、栏头文字完全不变，唯一线索是 1,200px 外右上角换了两个按钮（[UI_AUDIT.md](UI_AUDIT.md) 详情第 10 条）。

口径：**进入编辑态必须在光标要去的地方有形态变化。** 栏头文字改「德语译文 · 正在编辑」，栏体加输入态边框与极浅底色，栏头右侧显示校验状态。

### 9.4 保存与冲突

| 情形 | 做法 |
|---|---|
| 保存中 | `Button loading`，文案不变（不改成"保存中…"） |
| 保存成功 | `message.success` 短提示 + 吸顶头的状态 `Tag` 同步更新 |
| 409 冲突 | 统一的 `ConflictRecovery`：一句话说明 + 一个"载入最新内容并保留我的修改"按钮 |
| 校验有问题 | 标签页 ⚠ + 通过按钮的 `Tooltip` + 就地 `help`。**永不禁用保存** |

最后半句是这个产品的既定原则：`/check` 的结果是给人看的辅助，不是硬闸——她可能有正当理由改一个金额（原文本来就写错了）。`web/api/app.py:179-187` 的 docstring 和 `TaskDetail.vue:142-144` 的注释都写了这条。迁移后要有测试守住（[BASELINE_BEHAVIOR.md §12](BASELINE_BEHAVIOR.md) B8）。

## 10. 渐进披露

### 10.1 三档

| 档 | 定义 | 承载 |
|---|---|---|
| **L1** | **不看它就可能做出错误的业务决定。** 常驻 | 直接在版面上 |
| **L2** | 有助于做这个决定的上下文。一次交互可得 | `Tooltip`、`Popover`、折叠、标签页、右栏 |
| **L3** | 技术、诊断、历史、说明、低频数据。二次交互可得 | `Drawer`、二级页面 |

L1 的判据是一句可以逐条套的话，不是感觉。[UI_ARCHITECTURE_PROPOSAL.md §8.3](UI_ARCHITECTURE_PROPOSAL.md) 有逐条套过的表。

### 10.2 四条不许藏

这四条是 `web/DESIGN.md §6/§9/§10` 明确要求可核对的业务事实，无论版面多紧都必须常驻：

1. **缺德语图**（`images[].de_present === false`）——藏起来会发出英文图；
2. **源文已变更**（`text.stale`）——藏起来会基于旧原文通过；
3. **落地页未确认**（`localization_validation.issues`）——藏起来会发出没确认的德国站链接；
4. **同渠道 90 分钟冲突**——藏起来会撞车或被拒。

### 10.3 反过来：不许常驻的

| 类别 | 现状例子 |
|---|---|
| 系统行为说明 | `保存不会自动删减超出上限的标签。`、`这里保存本篇选择，不修改全局映射表。` |
| 缺失的解释 | `这张没有程序生成记录（没跑过德语图，或当前用的是人工放置的图）。`——没有指标就不渲染指标区，不需要解释为什么没有 |
| "一切正常"的宣告 | `没有硬闸告警`、`都看过了`（后者可以留，它是进度而不是宣告） |
| 实现细节 | `{{link1}}`、`prompt v1 · provider / model`、`帖子 122100548013379375：…账本…`、`detect Chrome 9224 … HTTP 429` |
| 尚未发生的状态 | `尚未进行英文语义风险预扫；请人工检查双关、歧义和美国特定表达。`——26/26 篇都是这个状态，它不是这一篇的特征 |

## 11. 告警

### 11.1 强度与后果对齐

| 后果 | 形态 |
|---|---|
| 可能发错内容 / 撞车 / 花错钱 / 提交被拒 | 满宽 `Alert`（`error` 或 `warning`）+ 一个动作 |
| 这一处需要人确认 | 正文内标记 + 当前那处的说明条 |
| 某项还没做 | 状态标记（中性色），不是告警 |
| 系统行为说明 | `Tooltip` 或不显示 |

### 11.2 只有四种情形配得上满宽 Alert

| 条件 | 类型 |
|---|---|
| 第三方作者待授权（`capabilities.third_party`） | `warning` + consent 复选 + 动作 |
| 组装告警（`meta.compose_warnings` 非空，主要是"缺德语图，已回退原图"） | `warning`，可折叠 |
| 风险扫描 `failed` 或 `stale` | `warning` |
| 冻结账号只读（`read_only`） | `info` |

**`risk_scan.status === 'not_scanned'` 不出 Alert。** 现状它命中 `.status-not_scanned` 拿到黄底黄边（`RiskPanel.vue:47`），而真实归档 26/26 篇都是这个状态——于是她每天看几十次同一块什么都没发生的黄色，第三天就学会忽略黄色，而黄色是"语义风险"的唯一载体（[UI_AUDIT.md P0-5](UI_AUDIT.md)）。

`completed` 且零风险也不出 Alert：没有风险不需要一块面板说没有风险。

### 11.3 成功不用 Alert

成功用 `message.success`（短暂）或状态 `Tag`（持久）。满宽绿色横条会把"一切正常"变成一个需要阅读的东西。

## 12. 动效

**2/10。只有状态过渡，没有入场编排。**

| 允许 | 时长 |
|---|---|
| hover / focus / active 的颜色与边框过渡 | 120–180ms，`cubic-bezier(.4, 0, .2, 1)` |
| 折叠展开、抽屉滑入、弹层淡入（antd 默认） | 组件默认，不调 |
| 加载骨架的微弱脉动 | antd 默认 |

**禁止**：列表项入场动画、页面切换过渡、数字滚动、滚动视差、任何装饰性动效。

**`behavior: 'smooth'` 全局禁用。** 不是风格判断——`TextCompare.vue:36-38` 记录了实测：内嵌 Chromium 里它静默不动，不报错也不滚。而"下一处"是这个页面唯一不能失灵的东西，它失灵时界面看起来完全正常（标记确实高亮了），只是跳不过去，而人会以为自己已经看完了。

`prefers-reduced-motion: reduce` 下全部降到 0.01ms（现状 `styles.css:173-179` 已经做了，保留）。

## 13. 无障碍底线

不是加分项，是底线。现状做到了一半（[BASELINE_BEHAVIOR.md §10](BASELINE_BEHAVIOR.md)）。

| 项 | 要求 |
|---|---|
| 焦点环 | 全局 2px 主色 outline + 2px offset。**任何地方都不许去掉它而不给替代**（现状 `styles.css:74-78` 这条注释写得好，保留）。⚠️ **Stage B1 实测**：antd 自己有八条组件级 `:focus-visible`，特指度到 0,4,0，全都写死 `outline-offset: 1px`，会在同一屏上造出两种焦点环。追选择器等于把 antd 的内部类名抄进我们的样式表，所以 `global.css` 用 `!important` 一次说清——和 `prefers-reduced-motion` 同一个手法，理由也一样：这是底线，不接受组件覆盖 |
| 键盘可达 | 所有交互元素可 Tab；标记地图必须可达（现状 `aria-hidden` + `tabindex="-1"`，等于对键盘不存在） |
| 模态框 | 打开时焦点进入框内、Esc 关闭、焦点陷阱、关闭后焦点回到触发元素。用 antd `Modal` 直接满足（现状三条都不满足） |
| 页面标题 | 每个界面一个 `h1`（现状详情页没有） |
| 标题层级 | 不跳级，同级同字号 |
| 对比度 | 正文 ≥ 4.5:1，12px 元信息 ≥ 4.5:1（不是 3:1——小字号不适用大文本豁免） |
| 状态传达 | 颜色 + 图标/文字，不只靠颜色 |
| 动态区域 | 错误 `role="alert"`，状态 `role="status"`（现状已做，保留） |
| 中文语境 | `lang="zh-CN"`，antd `locale={zhCN}`，日期选择器不能是英文 |

## 16. Stage J 最终视觉定值（2026-09-13）

已在 1366×768 与 1920×1080 的 20 张正式页面截图上核对，原始值见 final-measurements.json。审校/历史行高 48px，首屏 12/19 行，历史分页首屏可达。顶部 48px、详情吸顶条 56px；窄屏隐藏分类列，不折行。

正文保持 15px / 1.7、Grid 1:1、独立内滚。正文高度为 viewport − 380px，图片为 viewport − 528px；第三方授权区存在时额外预留 112px，全部来自 theme.ts。图片可进入放大 Modal。初翻授权采用 warning Alert，付费按钮保持 default 并显示金额口径；后台不可开始时不重复展示可提交的授权表单。

error 为浅红底与深红实线；warn 为浅红底与浅红实线；risk 为黄褐色下划线。视觉重量 error > warn > risk，重叠算法仍严格 error > risk > warn。终态中性，行级降饱和；分类和正文话题标签不计作告警。列表逐行真实状态数量随可见行数增长，不适用“全屏最多 8 个”的泛化旧指标。

详情默认视图（正文、图片、标签、第三方）在小屏为 1.20–1.48 屏，bordered regions 1–3；唯一 primary 是保存或创建排期，冻结归档为 0 个。月历几何检测的 33 个边框包含日格，详情的 3 区块上限不套用于日历网格。六个界面均只有一个 h1，同级字号一致。

焦点环沿用 2px / 2px；低动效将过渡和动画压至 0.01ms。保留 antd Modal/Drawer 的关闭与恢复，仅补首尾 Tab 循环；关闭后的隐藏浮层不再抑制正文快捷键。完整回归见 Stage J 报告。
