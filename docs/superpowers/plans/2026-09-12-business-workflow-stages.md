# 业务功能分阶段实施记录

本文件保存 2026-09-12 当时的实施分工和结果，其中 Vue 仅描述当时版本。当前唯一前端与验收状态见 [五阶段实施清单](../../OPTIMIAZATION.md) 和 [审校台说明](../../../web/README.md)。

依据：`REQUIREMENTS.md` 及其指定的后续修订 `FUNCTIONALITY.md`、`CONTEXT.md`。前一批提交 `701b1f8` 已完成原稿保护、人工文案真实保存和发布缺图保护。本记录承接开发，不改写业务决定。

## 本轮顺序

1. **监测**：切换 `.global` 并冻结 `.tech` 自动消费；分离探测 Chrome；按上海在岗窗调度、首屏增量、晨间兜底、按天保留抓取记录。提供可预览的常驻调度入口和 Windows 模板。
2. **抓取与留档**：月份目录、稳定摘要名、产品标签，旧布局可读且迁移必须显式执行；SQLite 只由本地真相重建，只用于展示。捕获源帖编辑并留存前版。
3. **本地化的共同前置**：FB 与 IG 各自成为候选，不跨平台合并、不等待 30 小时、不复用译文或图片。旧发布记录仍保留幂等保护。链接、标签和模型优化操作建立在这一边界上继续实现。
4. **审校**：接通挂起、跳过、恢复、人工接管、资源导出、标签编辑；事件追加留痕，保留版本冲突保护。调度器唤醒到期挂起项。
5. **发布**：保持同渠道时间间隔、平台选择和回读的证据要求；没有实测证据时在浏览器前停止。随后接真实批准、完整月历、飞书通知及镜像。

## 本轮协作边界

- 监测代理：配置中的 targets/detect/delta、Chrome、抓取、调度器与启动模板。
- 存储代理：store、SQLite、layout 工具、存储测试；向调用方提供兼容路径函数。
- 审校代理：review 事件、Web API、Vue、审校测试。
- 主代理：pipeline 独立路由、publish、各模块集成与整体验证。

使用现有 `.venv` 和离线夹具验证。真实归档不迁移；开发过程中不调用付费模型、不发送飞书消息、不安装计划任务、不发布社媒帖子。上述外部行为需先满足代码已有的真实证据及配置条件。

## 阶段一：发现新帖子

已接通 `.global` 监测，旧 `.tech` 保留归档并计入历史成本，不进入新的自动处理。探测、回填、发布分别使用 9224、9222、9223 及独立 profile。上海 08:00–19:00 按 60 分钟轮询，其余时间 180 分钟，均有抖动；每天 07:00 附近单独随机深扫兜底。一次维护在两平台扫描结束后处理内容，避免重复抓取。

调度时刻先落盘，进程锁防止重入，重启不密集补跑错过的轮次。视频等跳过类型显式计数；增量 capture 按天保留，回填记录不参与清理。上个自然月的发帖分布和早班预算余量可在预检查看。作息与兜底时刻目前由配置指定，根据发帖分布自动改写兜底时刻尚未实现。

预览：`python -m pipeline.scheduler --preview`。生成 Windows 模板：`python -m tools.schedule scheduler-xml`。实际运行需 `--run`；同时处理模型任务需另加 `--process` 并满足激活与预算条件。不要同时运行旧每日增量任务和新常驻入口。本轮没有安装任务或执行真实回填。

出口检查也已接通常驻维护与只读 preflight：`[network_evidence]` 默认关闭，启用后按小时使用 `IPINFO_TOKEN` 查询本进程出口，保留最近 20 个 IP/ASN 样本。Lite 不提供类型，显示未知；Core 需要相应服务权限。出口变化、代理/托管标志与连接失败分开处理，不能用 IP 信息服务的失败判断社媒账号被封，也不能把此进程的出口当成 Chrome 代理路线的证明。依据：[IPinfo Lite](https://ipinfo.io/developers/lite-api)、[Core](https://ipinfo.io/developers/core-api)。

## 阶段二：保存原帖与可追溯版本

新布局是 `posts/YYYY-MM/日期_正文摘要_帖子ID/`，摘要首次创建后固定，旧平铺布局仍能读。原文更新保存前版，变更的原图使用独立文件名，人工稿与人工图片保留。产品分类可自动预填、人工修改与筛选。

SQLite 只服务列表查询，从本地文件重建；失效时重建，失败则退回文件读取。翻译、预算、审校和发布不读取数据库作业务判断。迁移预览：`python -m tools.layout migrate instagram --dry-run`；重建展示索引：`python -m tools.layout reindex-db`。本轮没有迁移真实归档。

飞书云盘镜像按产品主分类和月份保存源帖、批准快照、成功排期快照；第三版表示已创建远端定时任务，不代表已到点公开发布。`state/` 备份等待文件稳定后生成；坏源帖不阻断已冻结条目的投递。没有反向同步。上传成功但本地回执丢失时，重试可能留下重复云端对象，但不会覆盖旧快照。实际权限和上传尚未联调。

## 阶段三：生成德语稿并允许人工修订

FB、IG 各自成为独立候选，不合并、不等待、不复用；旧双渠道发布记录继续保护幂等。

第三方作者只入档，等待运营在本篇点“翻译这篇”。许可追加到 `paid_consent.jsonl`，绑定完整源文、作者关系和原图字节，不扩大 `trusted_owners`。变更后许可失效；预算、完整素材、账号归属、价格检查仍保留。后台复用原翻译和图片执行器，生成结果回到本篇审校，不自动发布。

正文、标签、链接分区编辑。短链从模型正文、风格例文和优化指令中移除。FB 使用只读映射表或经确认的本篇德国站链接，IG 使用引导话术和只读 bio 地址。品牌及型号标签保持原样，普通标签可以选择德语候选，保存时确认。计数器接近上限时提示，不自动截断或压缩。

标签推荐给出 3–5 个语义候选，能按带时间、地区、来源的采样证据排序。当前没有已验证的 IG 热度接口、Google Trends 访问资格或业务提供的同类德语账号名单；实际采样返回不可用，界面明确按语义推荐，不声称是“德国热搜”。[Google Trends 官方 API](https://developers.google.com/search/apis/trends) 需要申请访问，不能假定已可接入。

提示词模板只读，运营输入只作用于本篇的优化要求。文案结果作为候选，采用后进入编辑框，保存才增加人工版本；图片结果使用独立版本文件，人工图优先。同一图片最多受理 3 次优化，失败也计入次数；界面展示估算依据，费用按真实 usage 记账。普通后台对账会保留已按人工稿生成的图片，不按旧机器稿重复付费。

任务有持久记录、重复点击保护，以及每次付费请求前的预算和源版本检查。进程中断留下的 pending/running 不自动重放，需先核对付费账本。翻译提示词版本升为 6，旧机器稿可能需要重译，人工稿优先规则不变。

## 阶段四：推送待审与故障信息

飞书支持待审、积压、排期成功、排期未确认、系统告警五类消息。运营与开发者使用不同 open_id 组；在岗逐篇提醒，离岗业务消息积压后早班合并；系统告警不静默。14:00、18:00 有积压才提醒，说明数量及最早等待时间。

卡片包含平台、账号、原帖时间、首图预览、德语摘要、待处理提示、原帖及审校页链接。预览图失败时仍发文字提醒。集合和 UUID 在发送前固定；重试不混入新内容，超过不确定回执窗口后待人工核对。跳过、挂起、接管的旧提醒撤出待发队列。

外部心跳说明调度进程仍活跃，不代表每个业务任务都成功。外部服务负责发现本机停止运行，不能由飞书静默推断机器健康。

| 默认关闭的接入 | 启用前需配置 | 本轮实际验证 |
|---|---|---|
| 飞书消息 | `[feishu]` 审校台 base_url、两组 open_id；`FEISHU_APP_ID`、`FEISHU_APP_SECRET` 环境变量 | 假 HTTP；没有发消息 |
| 飞书云盘 | `[mirror]` 授予应用写权限的 root_folder_token；同一应用凭据 | 临时文件、假上传；没有上传 |
| 心跳 | `[heartbeat]` 与 `HEARTBEAT_URL`；外部服务的缺席通知 | 假 HTTP；没有联系真实服务 |
| 后台月历 | `[calendar] enabled`，默认每小时刷新 | 同一发布锁，繁忙跳过；没有操作真实浏览器 |

飞书契约核对：[消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[图片接口](https://open.feishu.cn/document/server-docs/im-v1/image/create)。接口测试不能代替企业应用授权和收件人可见范围验证。

## 阶段五：审校决定、排期与人工接管

追加账本保存待审、已编辑、已挂起、已批准、已排期、不发、已交人工。挂起默认 3 个上海工作日，由调度器到期恢复；不发需填写原因。下载先准备 ZIP，成功后记录人工接管，可重复下载并回填手工发布链接。操作人暂为 `actor: null`，未引入账号权限系统。

批准接受运营指定的柏林时刻，明确处理夏令时，不依赖本机或浏览器时区。同渠道默认间隔 90 分钟，冲突拒绝并给最多三个可选时刻，不自动顺延。月历展示远端可见卡片，失败保留旧数据并显示新鲜度；缓存只帮助选时，不能作为提交依据。

提交持有全局发布锁，复核版本、素材和时刻，冻结正文图片，记录 approved 后调用浏览器。填好 composer 后、允许点击前再次实时检查间隔。只有远端成功回读才记录 scheduled、回执和云盘第三版；模糊结果保留账本，禁止自动重试。

**实际提交仍被证据闸阻止**：目前 probe 缺少单渠道勾选、对应目标账号及单渠道回读证据，`publish/channels.py` 在浏览器前停止，Web 禁用按钮并说明原因。长文案回读已有诊断和离线验证，真实 G6c 成功证据仍未补齐；完整月历的渠道识别也需在实际页面验证。没有伪造 selector、远端任务或成功回执。
