# 待审帖子详情页重设计：逐项功能规格

## 目标与边界

本文逐项列出用户已确认的 Q1–Q49 决策，描述目标行为，不代表代码已经实现。页面面向业务人员，围绕对照原帖、审核德语正文和图片、核定发布标签与链接、确认最终排期组织信息。同一路由仍需正确展示已冻结、已排期和其他处理状态。

可见界面只保留对业务审核与决策有用的事实。业务时刻统一采用现有 Asia/Shanghai 基准转换，但界面不显示城市、时区或地点名称。原帖来源账号与实际发布目标账号必须区分。归档、模型、费用和诊断数据留在后台。

## 一、页面结构与导航

- **D01（Q1）**：内容审核与创建排期保留在同一详情路由；先审核、冻结内容，再在同页选择排期。重开页面可查看已完成决策与结果。
- **D02（Q2）**：有四个主步骤，每步显示真实完成状态。可自由跳转和返回，不设强制线性向导；冻结和提交条件仍由服务端核验。
- **D03（Q3）**：来源信息只显示平台、来源账号与实际作者、原帖时间、原帖链接，以及适用时的合作方／第三方归属。隐藏归档路径、分类方式、首次归档时间、索引、云盘、存储状态。发布目标账号仅在最终确认中明确标出。
- **D04（Q4）**：从当前内容和校验结果生成可点击待办，写明哪段正文、哪张图、哪条链接需要处理并直达对应步骤。扫描标记为零不自动说明内容安全。
- **D05（Q5）**：四步固定为①德语正文与原文／风险对照，②逐张图片，③发布标签与链接，④最终确认与排期。商品分类是辅助信息。
- **D07（Q7）**：首次进入默认打开第一个未完成步骤；有效 URL 步骤深链优先。切换步骤更新 URL，保留原列表筛选和返回位置。
- **D30（Q30）**：仅保留一个紧凑页头，含返回、上一篇／下一篇、来源身份、平台、业务状态、步骤进度。删除重复标题、常驻零问题计数、已看图片计数、过早出现的禁用冻结按钮。
- **D31（Q31）**：待办默认最多显示优先级最高的三项，其余可展开；无待办时只显示一句简短说明。
- **D33（Q33）**：不常驻显示运行状态正常／未知。已核实影响当前动作的故障，在动作附近说明问题和下一步。
- **D34（Q34）**：原帖时间、选时、冲突、最终确认、结果和处理记录采用同一业务时刻基准。可见文案不出现“上海”“上海时间”“柏林”等城市或时区字眼。
- **D35（Q35）**：商品分类仍可编辑，放在来源附近的紧凑辅助位置或更多信息里，不占一个主步骤。
- **D41（Q41）**：步骤间切换保留草稿；带未保存草稿离开到列表、另一篇或浏览器历史位置时，提供继续编辑、保存并离开、放弃修改并离开。保存失败或保存时又有新输入则不离开、不丢草稿；保存正文不等于确认正文。
- **D45（Q45）**：页头下方是横向四步导航，状态不能只靠颜色表达；窄屏使用紧凑选择器，不让整页横向滚动。
- **D46（Q46）**：沿用蓝、白、浅中性色；以字级、轻分隔线和适度留白建立层级，减少套叠卡片及大块空白，强警示色只给行动问题。
- **D48（Q48）**：保存和确认动作放在当前步骤末尾。尚不可冻结时显示可导航的待办，而不是常驻禁用主按钮；条件满足后在最终步骤给出冻结动作。
- **D49（Q49）**：帖子不再符合当前列表筛选时，明确说明并保留返回原筛选列表；不显示虚假的第 N／共 M 位置。相邻帖子无法可靠计算时禁用前后切换。

## 二、持久审核确认与发布闸门

- **D06（Q6）**：显式保存正文确认及每张拟发布图片的独立确认，记录时间与内容版本。系统没有登录身份，不虚构审核人；阅读或打开内容不算确认。
- **D09（Q9）**：正文确认仅覆盖德语正文，标签和链接另行决策。内容合适且未编辑过的机器初稿也允许显式确认。
- **D10（Q10）**：每张图都有“确认本张用于发布”；选择原图可用“使用原图并确认”一次完成两件事。单纯浏览图片不算确认。
- **D11（Q11）**：来源正文或德语正文变化只让正文确认失效；原图、图片顺序、所选版本或图片字节变化只让受影响图片确认失效；标签或链接变化只清除对应分区确认。
- **D25（Q25）**：标签与链接步骤给业务人员一个完成动作，后端分别保存两个决策。真正空白的分区无需勾选；原帖有标签但人工全部删除，仍需确认该选择。
- **D26（Q26）**：单篇、CLI 和批量入口的每次新真实提交，都在不可逆点击前复核当前正文和全部现有图片确认。只读预览与 ready 候选准备不受影响；旧冻结／排期记录不补造确认、不改写。
- **D47（Q47）**：无图片帖仍有图片步骤，说明“本篇无需审核图片”，不生成假确认。发布器的静态图片适用范围照旧，历史无图帖不能被暗示为可直接排期。

## 三、德语正文

- **D13（Q13）**：桌面端英文原文和德语正文左右对照；短文自然高度，长文两侧各自滚动；窄屏上下排列。
- **D14（Q14）**：无德语正文时明确显示空状态，提供手写填写和生成初稿；空内容不标为机器初译，也不因零扫描结果暗示已审核。
- **D15（Q15）**：区分未扫描、扫描失败、结果过期、扫描完成；前三者说明没有有效扫描，但不阻断人工审核和确认。规则／语义风险定位到可点击文字并解释；成功零结果不显示大幅成功提示。
- **D16（Q16）**：在右侧德语区编辑，先独立保存，再确认当前保存版本。未修改机器初稿可确认；新正文保存后须重新确认。

## 四、逐张图片

- **D17（Q17）**：一次展示一张原图与拟发布图，完整显示并保持比例。多图用编号缩略图及逐张确认状态；单图不显示多余翻页控件。
- **D18（Q18）**：没有德语图时，拟发布侧明确显示暂无可用图，提供使用原图并确认、上传、生成。未显式选择原图前，不把原图复制成已选拟发布图。
- **D19（Q19）**：有其他版本时，以次要入口展示当前版与候选版视觉比较、简短修改指令和采用动作。隐藏路径、模型、数值图像指标及金额；采用新版本会使该图确认失效。
- **D20（Q20）**：形变或缺少可见变化值得复核时，仅在受影响图片旁给出简短、可执行且承认不确定性的提示；不武断判对错，不显示 dHash、像素比例、放大倍数或耗时。
- **D43（Q43）**：来源图片缺失／损坏时，在对应图片和待办里注明序号及下一步；无法查看的图不能确认。健康图片不显示存储计数。

## 五、发布标签与链接

- **D21（Q21）**：业务人员可新增、修改、删除全部拟发布标签，包括品牌和型号，也可选空列表。先展示最终选用标签，仅在与原帖不同的时候展示差异；只保留平台语法和数量限制。
- **D22（Q22）**：Facebook 每条来源 URL 与一条德语目标 URL 成对显示，可打开目标核对；未填目标给明确待办。普通页面不展示底层映射配置或内部占位符写法。
- **D23（Q23）**：编辑 Facebook 正文时，以“插入链接 1”等动作将对应链接放在光标处。最终预览展示真实目标 URL；有效但未使用的目标链接只在文末补一次。
- **D24（Q24）**：Instagram 选用了 bio 引导话术却未配置 bio 目标时提醒，但不阻断分区确认或真实提交。
- **D28（Q28）**：上述 bio 目标缺失提醒同时出现在链接步骤和最终确认，直到条件消失；它不是硬闸。
- **D38（Q38）**：德语标签建议只展示候选词及其与原帖标签有依据的简短语义关系；勾选不自动改变最终标签。隐藏趋势值、采样时间、比较组、原始证据，不捏造效果结论。
- **D44（Q44）**：Facebook 一条来源 URL 对应一条目标 URL，保持原始顺序。业务人员可改目标及正文放置位置；本轮不新增或删除对应链接行。

## 六、最终确认、排期与结果

- **D27（Q27）**：冻结前是精简总览及未完成事项，可按需展开完整文案。提交前弹窗展示冻结的完整文案、顺序图片、发布目标账号、唯一渠道、所选时刻。
- **D29（Q29）**：选时显示所选日期／时刻、有效范围、附近同渠道冲突或不确定性；冲突时给替代时刻。普通界面隐藏缓存诊断和全天占用，提交前仍复查真实占用。
- **D39（Q39）**：第四步可按需展开和复制服务端准确渲染的完整文案，最终弹窗始终显示它。仅临近平台长度限制或校验出错时显示字符数；不复制前端近似拼接稿。
- **D40（Q40）**：翻译／出图状态留在相关步骤；排期有明确提交中状态。结果不确定时只引导核对已有尝试，不提供重复提交。scheduled 表示远端定时任务已回读确认，公开发布仍是另一事实。

## 七、辅助动作与不同状态

- **D08（Q8）**：机器翻译、文案优化、出图／修图作为相关步骤里的次要工具，按需使用。
- **D12（Q12）**：详情页不显示费用估计或实际金额、模型标识、技术诊断、原始处理记录、查看处理依据。付费动作可简述使用模型额度，图片优化显示准确剩余次数；预算、许可和授权检查继续由服务端执行。
- **D32（Q32）**：暂缓、唤醒、跳过、转交、下载等次要动作放入“更多”；在有关位置展示完成后的业务状态或原因，不占用主审核区。
- **D36（Q36）**：冻结帖重开后引导选时；已排期帖显示结果；暂缓帖显示唤醒时间／动作；跳过与转交帖显示决定和理由。内容仍可查看，完成状态不展示不能操作的四步待办。
- **D37（Q37）**：从“更多”打开业务处理记录，只展示有意义的决定、时间和理由；不显示技术 JSON 或日常处理流水。
- **D42（Q42）**：来源区标明第三方作者及原帖链接。只有发起需来源许可的模型动作时才显示简短说明并要求显式同意；解决后不常驻占空间。

## 验收边界

1. 刷新后仍能读到正文及逐图确认；版本变化只清除受影响确认，失效确认不能复活。
2. 冻结和所有新真实提交路径在不可逆动作前拒绝缺少当前确认的内容；旧证据保持可读，只读准备仍可用。
3. 最终弹窗的准确文案、链接、标签、图片顺序、目标、唯一渠道和日期／时刻与所提交的冻结内容一致；后台刷新不改动已打开弹窗。
4. 正常与异常状态均能让业务人员不接触路径、技术指标、原始 JSON、金额或时区地名就理解下一步。
5. 验证使用隔离夹具，不连接真实账号、不调用付费模型、不创建真实远端排期；离线通过不写成真实联调通过。
