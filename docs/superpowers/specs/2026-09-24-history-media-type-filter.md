# 历史归档列表：帖子类型筛选与缩略图规格

## 目标与边界

本文逐项记录已确认的 Q50–Q53 决策。当前历史列表对非静态图文帖使用灰底单图标，视觉上与真实图片缩略图割裂；同时业务人员需要按源帖实际内容类型筛选。此功能只改历史列表及其详情返回上下文，不新增平台请求，也不扩大可发布帖子范围。

现有 preview_kind 表示“这一行现在能展示何种预览”；新增 post_type 表示“源帖实际包含什么类型的内容”。图片字节缺失或缩略图请求失败不会改变源帖类型。

## 逐项功能要点

- **H50（Q50）**：新增一个帖子类型筛选：全部类型、静态图文、纯图片、视频、图片＋视频、纯文字、类型待核对。依据归档的来源媒体种类和原帖正文分类；来源媒体列表不完整、类型未知或证据矛盾时归入“类型待核对”。不靠画幅比例或播放图标猜测 Reel。
- **H51（Q51）**：保留当前缩略图大小和圆角。无本地真实图片时，按类型绘制不同的小型画面：视频框与播放符号、纸张和文字线条、图片／视频分割画面，并使用克制、对比度足够的配色。图片＋视频帖若有可用原图，则显示真实原图并叠加小播放标识。插画只说明类型，不伪造帖子画面，不抓取远端视频封面。
- **H52（Q52）**：在历史列表原有平台、月份、产品分类旁增加一个“帖子类型”下拉框，并提供明确的“全部类型”。切换类型时回到第一页；筛选值写入 URL，并随详情链接、返回链接和上一篇／下一篇查询传递，使翻页及返回仍在原筛选集合内。
- **H53（Q53）**：“图片待加载／不可预览”只是缩略图状态，不是帖子类型，不能作为筛选项。来源明确有图片的帖子，即使本地文件缺失或 HTTP 请求失败，仍保留静态图文、纯图片或图片＋视频等真实类型；只有来源媒体证据不足才进“类型待核对”。

## 类型判定契约

| 归档中的来源证据 | post_type |
| --- | --- |
| source_media_complete 为假；已声明来源媒体数与列表矛盾；媒体结构错误；出现未知媒体种类 | pending |
| 至少一张图片、无视频、原帖正文非空 | static_image_text |
| 至少一张图片、无视频、原帖正文为空 | image_only |
| 至少一个视频、无图片 | video |
| 图片和视频同时存在 | image_video |
| 确认媒体列表为空，原帖正文非空 | text_only |
| 确认媒体列表为空，原帖正文也为空 | pending |

优先读取布尔值 source_media_complete。旧记录若该字段缺失或为空，则以 media_complete=false 表示来源证据不足；否则依据已有媒体列表判断。当前记录的 media_complete=false 还可能只是已知图片下载失败，不能覆盖明确的 source_media_complete=true。本地图片是否存在只决定 thumbnail_url 与 preview_kind，不参与上表。SQLite 展示索引和归档文件回退使用同一个纯分类函数；新字段可重建，不覆盖 post.json 或其他真相源。

## 列表、筛选与无障碍行为

- 缩略图固定占 40×40 像素，行高维持 48 像素；窄桌面宽度也不因插画撑高行或挤乱文本。
- 每种插画回退都有可访问的类型名称，装饰图形对读屏器隐藏。真实缩略图可保持装饰性，因为旁边的帖子摘要才是主链接；混合帖的播放提示仍应有类型说明。
- 真实图片请求返回错误时切换到“图片不可预览”插画，保持 post_type，不由列表渲染器自动重试。
- 平台、月份、产品分类、帖子类型按 AND 合并，在分页及总数统计之前筛选。有效筛选在刷新、进入详情和返回时仍存在。
- 索引读取失败时，现有归档文件回退给出相同的类型筛选结果、总数和排序。缺失或非法类型参数归一为“全部类型”。
- 帖子类型是源帖内容分类，不等于可编辑产品分类、审核状态或发布状态。

## 验收边界

1. 离线夹具覆盖六种类型、来源媒体不完整／未知、混合帖真实图片、本地图缺失和实际 HTTP 404 缩略图。
2. SQLite 和归档文件回退对组合筛选、总数、分页及顺序结果一致；浏览器无须先加载所有历史帖子。
3. 前端验证全部类型选项、各类型名称、URL 与返回上下文、40 像素缩略图、48 像素行高，以及插画行不请求图片。
4. 浏览器在两个宽度下用隔离夹具与真实 404 响应验收；不访问真实社媒账号。
