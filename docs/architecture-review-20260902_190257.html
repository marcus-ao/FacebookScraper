先修这五条：它们不是洁癖问题，是缺陷

这五条是审查过程中撞出来的真实问题，我逐条复核过。它们和「代码太长」无关，但都源于同一个病因：同一份逻辑被写了两遍，然后各自漂移。

① 同一个 429，翻译阶段整批崩，调图阶段只算单条失败

CONFIRMED

translate.py:597-604 localize_images.py:1418-1449

localize_images.py 里有 14 行注释详细论证了为什么 isinstance(exc, openai.APIError) 是错的——它是 RateLimitError(429)、 APITimeoutError、BadRequestError(400，含审核拒绝) 的共同基类， 「一张有问题的图可以永久堵住队列」——然后把它收窄成 4 类（CR-53）。

translate.py — 仍是被判定为错的旧实现
import openai
return isinstance(exc, openai.APIError)
localize_images.py — CR-53 修复后
fatal = (AuthenticationError, PermissionDeniedError,
         NotFoundError, APIResponseValidationError)
return isinstance(exc, fatal)

config 里 request_gap_seconds = 1.0、待译 1,051 篇——429 是可预期的。而 translate.py:1058 还会打出「API 鉴权/端点/模型或请求配置属于整批共享错误」这条与事实不符的文案。CR-53 的修复只落到了两个副本中的一个。

② 两个 dHash，同名同算法，重采样滤波器不同 → 同一张图算出不同哈希

CONFIRMED

pipeline_assisted.py:355-372 localize_images.py:873-886

pipeline_assisted.py — 编排层配对判定
.resize((9, 8), Image.Resampling.BILINEAR)
localize_images.py — 产出结构相似度
.resize((9, 8), Image.Resampling.LANCZOS)

两处都叫 dhash / dhash_distance，签名不同（一个收 Path、一个收 Image），滤波器不同，因此对同一张图给出不同的 64 位值。目前两者的消费者不重叠所以没炸，但这是一颗定时炸弹：任何人把其中一个的距离阈值搬给另一个都会得到错误结论。
