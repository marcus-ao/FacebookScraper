# 需求与共识

**基线日期：2026-09-12；事实同步至 2026-09-14。** 本文件定义做到什么才算满足业务需求，以及**每个验收单元现在是什么状态**。功能形状和编号以 [FUNCTIONALITY.md](FUNCTIONALITY.md) 为准，证据能证明到哪以 [HANDOFF.md](HANDOFF.md) 为准，人工操作顺序在 [MANUAL_STEPS.md](MANUAL_STEPS.md)。

五阶段与八批实施范围已经接受。本文列需求，不把"入口存在"或部分测试通过写成业务完成；每个验收单元独立判断。

## 0. 状态词

全项目共用这五个词。**一行只能用一种状态**；宽功能按子项拆行，已知代码缺口不能只列外部依赖。

| 状态 | 判据 |
|---|---|
| 代码未完成 | 验收单元有已知实现、恢复、失败闭合或必需接口/界面缺口；已有部分代码或测试不能关闭整个单元 |
| 离线通过 | 该单元所需行为存在，且有对应离线证据；不表示真实账号/企业权限/远端结果成立 |
| 待真实联调 | 该行代码前置已具备，剩余是明确的真实数据、人工操作、权限或远端验收 |
| 真实通过 | 有日期、真实输入、结果和可复核证据，**只适用于证据覆盖的范围** |
| 明确延期 | 已接受的范围决定，本轮不做；与缺陷或联调依赖分开 |

## 1. 目标与边界

系统面向一名上海运营，把美国站公开图文内容转成可审校、可追溯、可在德国站单渠道排期的内容。人的日常动作应集中在审校、修改、选择时刻和确认发布；系统负责归档、付费处理、确定性检查、状态留痕和失败闭合。

目标账号固定为：

| 平台 | 当前目标 | 处理规则 |
|---|---|---|
| Facebook | `neakasaofficial` | 独立抓取、独立审校、只发 Facebook |
| Instagram | `neakasa.global` | 时间线合作帖全部抓取；独立审校、只发 Instagram |
| Instagram 历史 | `in_neakasa.tech` | 冻结，只读；不得继续抓取、加工或发布 |

Facebook 与 Instagram 不配对、不合并、不共用发布候选。相同文案或素材也不能改变来源渠道。

本轮只处理有正文且媒体全部为静态图片的帖子。纯视频、图文混合、无媒体和无正文都要分类计数并可见，但不加工、不发布。

## 2. 用户与人工边界

本轮只有一名审校人，界面为中文，在岗窗为上海 08:00–19:00。她可以：

- 修改德语正文、语义标签、单篇链接覆盖和 Instagram bio 引导语；全局映射由业务明确维护，在 Web 只读；
- 查看并选择标签建议，标签建议不可成为发布硬依赖；
- 对每张图片发起最多三次优化；
- 挂起任务，默认三个上海工作日后恢复；
- 填写理由后决定不发，或下载资源后转人工处理；
- 选择任意合法柏林时刻；同渠道前后 90 分钟有占用时，系统拒绝并给出建议；
- 在看到最终文案、图片、账号、渠道和时刻后确认一次真实提交。

Web 运营设置只开放默认柏林时刻（默认 10:00/17:00，预填而非固定槽）和挂起工作日数（默认 3）。保存带配置版本 CAS，拒绝未知/受控字段，保留注释和无关参数。其它受控配置和提示词只读，原解释随界面展示，不能用确认弹窗代替权限边界。

机器不得覆盖人工文案或人工图片。源帖更新时保留人工劳动并标记需要复核，不静默丢弃。

本轮不做登录与 RBAC。所有审校事件必须保留 `actor` 字段，值固定为 `null`。未来启用身份管理前，不得把 `null` 解释成某个具体人员。

## 3. 监测与抓取要求

监测对象为 FB `neakasaofficial` 与 IG `neakasa.global`，两平台独立计数、调度、停机和归档。目标账号实际参与的合作帖保留真实 owner/coauthors。9222 只供人工 30 天回填；回填建立独立监测基线与启用时间，不触碰发布激活边界。9224 普通轮次只开主页首屏并被动读取 GraphQL/feed；每天一次北京时间 06:30–07:30 晨间轮次随机滚动 2–4 屏、每平台最多 90 秒。

每天含周末按北京时间 08–19 点 45–75 分钟、19–08 点 135–225 分钟抽样。scheduler、CLI、`--if-stale` 共用持久 `next_due`；19:00 保留已抽时刻，08:00 首轮落在 08:00–08:15 且距上次主页至少 45 分钟。普通/晨间不足 45 分钟合并并记原因。锁忙（退出码 75）不推进时刻，重启不补跑。月度和安静期统计只展示。普通轮次每平台最多 300 秒。

所有 9224 入口在导航前持久记录访问意图。主页限 24 次/平台/滚动 24 小时；详情限 1 次/帖/扫描、3 次/平台/扫描、12 次/平台/滚动 24 小时。真实浏览器 dry-run 也计配额和停机；preview 离线。缺初始化或坏状态失败闭合。CAS 恢复带 expected revision 与 reason，保留配额和访问历史。401/403/429、登录/checkpoint/challenge 立即全 profile 硬停且不再导航、滚动、下载；过期 CDN 403 仅单媒体失败，CDN 429 全局停机；三次普通失败暂停对应平台。

所有候选在首次下载前持久化。只有来源媒体结构不完整时才能打开一次匹配同平台、post ID、目标 owner/coauthor 的详情，且不滚动、不翻轮播、不重放 GraphQL；下载失败不触发详情。来源完整性与“来源完整且所有静态图片实际全图下载、解码、SHA 校验、原子落盘”分开记录。保留媒体顺序，每项一个尺寸；未知结构不完整，IG 重复封面/视频缩略图不计图片。

失败、配额或超时立即转人工，普通扫描不重试；人工恢复每帖显式一次并服从相同护栏。类别为 new/historical/source_updated/recovered/time_unknown。基线历史只汇总。视频、混合、无媒体、无正文归档和计数，但不建抓取卡、不进付费处理。内容 revision 使用正文与有序实际媒体 SHA，URL 签名/路径和重复响应不算变化。

阶段一固定 `process=false`，模型、标签、审校唤醒、月历、云盘镜像和发布通知均不运行。抓取卡异步、持久、逐帖发送，字段与链接见 FUNCTIONALITY F1；通知未知结果保留人工裁决。实际平台阻断与请求错误保留。

## 4. 内容与付费要求

归档必须记录来源平台、目标账号、真实作者、合作方、发布时间、永久链接、原文和每个媒体项。`account` 与 `owner` 不得混用；Instagram 是否在目标时间线上由 `parse.on_timeline_of()` 判断。

本地化编辑器把正文、语义标签和链接分开。品牌、型号、优惠码、@提及、合作方署名和需要原样保留的标签不得被机器改写；图片中的数值和单位不自动换算。不确定时保留原样交给人。

Facebook 可在正文光标处插入 `{{linkN}}`，由对应德国链接替换；未插入的有效链接在末尾追加，已插入的不重复追加。非法编号/缺目标/损坏占位符阻止通过，IG 不支持。即时 `/check` 使用完整当前本地化草稿，按替换后的最终正文、标签和链接/CTA 计数；返回前的估算必须注明，不能把占位符长度当成真实 URL 长度。

所有模型调用共用月度/每日预算和追加式付费账本。第三方来源先取得内容级许可。超预算、缺许可或远端计费状态不确定时失败闭合。重放不确定请求之前必须先核账。

模型任务关联拥有进程、job ID、paid request ID、source/prompt 版本和更新时间；中断批次以 operation_id 关联付费记录和费用。恢复区分正在执行、中断未请求、结果已落盘、远端可能已计费；持版本核对，恢复动作不隐含重试。旧候选在来源或提示词版本变化后不可应用，费用统计纳入风险扫描和不确定金额。相关恢复代码已有定向测试，真实供应商核账另验。

原文未变化与机器结果仍有效分开显示。`stale=false` 仅说明原文哈希未变，不保证提示词版本当前；界面/API 应说明机器版本和当前版本。当前旧 Facebook 机器译文为提示词版本 5、当前为 6，当前读取没有可接受的德语图，原 FB 目录未发现 media_de；这不能证明“曾有 FB 德语图但因版本失效”，也不能自动触发付费重做。冻结 `.tech` 的 3 张历史德语图不作新来源素材。

风险提示分两类：确定性检查来自本地规则；翻译前真实预扫描覆盖 `pun`、`ambiguous`、`us_only`，结果绑定源文与提示词哈希/版本、模型及时间。未扫、失败、成功零风险不能混淆；失败不称安全。页面只读取与当前内容绑定的实际扫描记录。

标签推荐的三类来源都在范围：Google Trends 公开 CSV 在同一英文标签的德语候选组内、`geo=DE`、相同时间范围/同批比较；IG 全球累计量级；德语同类账号近 14 天用词频次按周采集。三者分别保留原始值、来源、采样时间和 freshness/失败原因，不能混比不同组 Trends 分数或把 IG 全球累计称德国热度。空同类名单跳过，失败/过期降级为候选加人工选择；降级不免除三个采集器的实现责任。品牌/型号原样，默认标签数与原帖等量，不静默削减。

Trends 导出只接受与本次候选组、地域和起止日匹配的被动 CSV 按钮证据；登录按钮或普通链接不能替代导出控件。CSV 保留原始字节，兼容 BOM、CRLF、周/月日期；上下文必须绑定源文与原始数据摘要。429/challenge 持久停止，人工确认恢复后通过只读状态取得当前版本，再持锁 CAS 恢复，不能删状态或无版本重置。当前 Trends 与 `.global` 均真实遇到 HTTP 429 并已停止，尚无本轮三来源真实采样验收。

## 5. 存储与恢复要求

业务真相与派生物必须单向流动：

| 数据 | 角色 | 恢复规则 |
|---|---|---|
| `post.json`、原图 | 来源真相 | 原图 URL 可能过期，不假设能重下 |
| `translated.jsonl` | 机器译文真相 | 由付费结果产生 |
| `translated_human.jsonl` | 人工文案真相 | 不可由机器覆盖 |
| `review_items.jsonl` | 审校决定真相 | 损坏行必须显式失败，不能静默忽略 |
| `paid_requests.jsonl` | 付费真相 | 不确定项先核账 |
| `published.jsonl` | 发布真相 | 不可重建；丢失可能造成重复发布 |
| manifest / SQLite / HTML / Planner cache | 派生 | 可由本地真相重建，不参与反向决策 |
| 飞书云盘 | 单向镜像（**本轮不开，见 §9**） | 仅回读目录/任务元数据；原文原图不自动下载或恢复，新版本不覆盖旧版本 |

接续另一工作区或机器时，先停写并备份核对整个 archive/state/运行配置，含 `config.toml`、存在时的 `config.local.toml`、本机 `.env` 受控副本与解释器位置/版本。凭据不进共享证据。所有入口绑定相同数据和锁，保留 `published.jsonl`、付费账本和激活边界；不能“重新开始”清空。

⛔ 2026-09-14 运行数据整库清空，激活边界、发布账本与付费账本一并删除，**没有备份**。这是一次显式的业务决定（从零逐阶段打磨），不是事故；但它也意味着上面这张表在重建数据之前只有代码侧成立。周期备份与大型证据独立版本的代码已有离线验证，能力本身仍未真实验收。

源图变化必须按每张实际字节哈希、数量和顺序识别，同名同大小换内容、增删和换序都不能漏。保留人工稿/图并提示复核；已排期仅提醒，不改冻结内容。SQLite 与文件比较实际记录集合及字段，发现缺失/多余/不符后重建或只读回退，不能仅检查文件存在。

同名 `source_text_sha256` 全链路采用统一的来源文字规范并有 AST 守卫；原始风险扫描另存 scan_text_sha256 保护高亮偏移。最终提交文案/媒体的精确指纹不随来源文字规范改变，不能为了统一字段破坏冻结字节绑定。

云盘补送只能来自冻结内容快照。历史版本缺失时补送同一版本；当前内容已变化时不得用新内容冒充旧版本。

**本轮原帖存储契约：** 新目录时间与归档月使用发布时刻的北京时间；源 ISO 不改，首次归档时间单独记录。旧目录名及月份稳定，无可靠日期进 `undated`。产品 hashtag 完整匹配优先、正文补充，长型号优先、别名归一；自动分类随接受的源文更新，人工空数组和缺少来源的旧分类均保留。

原图须完整解码且记录实际 MIME、字节数与 SHA，先写临时文件再原子落盘，已有原图不覆盖。复用须匹配已有哈希，不能把有效图片格式当作原件未变化的证明。不完整平台响应不能降低媒体数量或保存进度；明确新版本下载缺图时保留已取得内容并标缺图。分类移动有账号锁及持久意图，历史记录保持原样，历史媒体和本地化所有权仍可定位。

SQLite v2 的 `posts/post_tags/post_media` 同时核验 SQL 列、分类/媒体顺序、外键、实际媒体哈希和 JSON 投影；候选库检查失败保留上一完整库。飞书内容身份不含分类/路径/镜像时间，但包括媒体可用性：补齐须形成含实际图片的完整版本。云端写入意图先落盘，回执未知停止重放，通过元数据及人工按操作 ID 结转。详情必须展示当前帖的状态，不能用全局已完成项替代当前帖证据。

## 6. 飞书要求

**消息通道是同一业务群的四个自建 webhook 机器人**（2026-09-15 用户确认，改写理由见 [FUNCTIONALITY §0.2/§4.4 F4-2](FUNCTIONALITY.md)）。`monitor_found→detect`、`monitor_saved→capture`、`ready/scheduled→publish`、`backlog/schedule_failed/morning/system→alert`。四个地址均须配置且各不相同；同群不报警，重复地址用 `duplicate_bot_targets` 报告并拒绝发送。发件箱只保存角色标签与冻结路由，不保存地址或签名密钥。

请求信封按机器人契约：`card` 是 JSON 对象而不是字符串，签名每次尝试重算（`timestamp` 超 1 小时失效），`code` 与旧版 `StatusCode` 两种成功响应都接受，其余一律失败闭合且异常文案不得带地址或密钥。机器人**不支持 `uuid` 远端去重、也不返回 message ID**：未知结果停为 `uncertain`，只有明确拒绝才退避重试；人工核对“已送达”填核对说明而非平台 ID。发送意图先落盘，崩溃后也不盲重放。

飞书卡片是审校入口。未尝试消息发送前重新读取当前状态，按帖子聚合，发现和处理同帖不重复计数；终结或挂起项退出待审。**卡片不带缩略图**（机器人没有图片上传接口）：当前有效首图是德语图还是原图仍写成文字，图片到审校台查看；重读当前稿失败要明示内容可能不是最新，不静默发旧快照。摘要用人工优先德语文案，并给来源/图片数、确定性检查和风险状态。

一旦尝试发送，本地投递 ID、接收角色与正文固定；签名信封不在冻结范围内，每次尝试重算。远端结果不确定先核对；当前角色的原卡仍有效时，人工 resolve 后补送保持同 ID/同内容。旧角色的未知投递确认未送达后，保留旧卡及裁决记录，再按当前阶段生成关联的新投递。聚合卡部分帖子失效时只为仍有效帖子向尚未收到的角色生成提醒，不重复已收者、不复活失效帖；兼容旧多收件人记录也必须遵守这一规则。人工误判未送达仍可能导致重复。缺机器人地址、当前稿重读失败、明确失败和不确定状态在运行页可见。

在岗窗即时推送，离岗到下一 08:00 合并；晨间摘要包含兜底补抓、分类跳过、处理延迟/失败、待审数量和最早等待。14:00/18:00 仅有积压提醒；无新增、积压、失败或可行动变化时不推空日报。机器向外部服务报心跳，缺席由外部观察者告警；不能依靠停机后也会停的本机告警替代。

outbox 默认保留 30 天终态热数据，完整关联事件/投递组件超期后按 SHA 归档，保留原卡片/UUID/回执与主状态去重索引。未决、待重试、待发送、离岗未发或仍有缺失收件回执的内容不归档；保留期不是按创建时间删除所有旧事件。

四个机器人已由用户创建，地址与各自签名密钥需要填入实际运行绑定的 `.env`；2026-09-15 用户已在群里收到四个机器人的自检响应，代表通道可达，不代表真实探测往返或运营可达的审校链接成立。云盘目录和权限仍需企业飞书应用与管理员授权，**本轮明确延期（§9）**。离线测试不等于这些已可用。

## 7. 审校、历史与排期要求

业务状态固定为七态：`pending_review`、`edited`、`snoozed`、`approved`、`scheduled`、`skipped`、`handed_off`。`skipped` 与 `handed_off` 含义不同，不能合并统计。

审校账本必须追加写、并发检查和版本检查。任一非空坏行、截断、非法状态/revision/时间都使读取失败并定位，不得跳过后计算“最新状态”。该严格读取已有定向证据，当前完整集成仍需回归。

日常任务聚焦当前待办；90 天是默认窗口，历史列表须服务端分页、总数、平台/月/tag/状态过滤并显式返回查询 range/page/total。详情按稳定 ID 查询，不受 90 天上限，冻结 `.tech` 可只读访问。查询不触发翻译或其它业务写入，也不为方便展示加载全部历史到浏览器。这些行为有离线覆盖；清库前也在 1,067 条真实归档上验过，但那份数据与证据已删除，需在重建后复验。

排期按柏林时刻让运营选择，按 Business Suite UI 时区验证可选范围。当前 UI 的同月边界是 2026-09-01 真机事实；系统必须在跨月时重新读取并适配当前可见范围，不能永久用固定“同一自然月”规则代替。

提交前和提交后都要按渠道检查占用。人工选的冲突时刻直接拒绝并给建议，不自动顺延。`scheduled` 只在远端回读确认后写入；它不表示到了发布时间后已公开。

月历必须读取完整可见月份的所有日期格/时刻条目，包含手工 Planner 任务和延迟加载。活跃时间建议不是帖子，月份标题或 35 格外壳不能证明完成；不完整/未知不能判为空档。选时用缓存提示，提交前持发布锁实时复核。公开状态另做只读观察并存时间/证据，无明确依据显示 unknown，不从排期到点推定公开。

每个发布入口都必须先冻结并展示同一份提交快照：最终正文、图片字节/哈希、单一目标渠道、目标账号、柏林时刻和来源版本。批准、CLI 或其他入口都不能绕过快照。

真实单渠道发布须有新证据证明渠道切换、目标账号、该渠道时间控件与提交后回读。2026-09-13T05:01:33Z 的实际月历读取已覆盖 35 格、4 条公开帖和 2 个已排除推荐时段，含 3 个独立 IG remote ID；这只验收本次月份读取。新提交回读仍需精确全文、完整日期格范围、唯一渠道/账号/remote ID 因果及最终图片证据；远端图片数量和顺序当前未知，不能由本地快照反推。资产 ID 或同一卡片的时间证据冲突时拒绝确认，旧双渠道 journal 不能作本轮 G8。所有入口共用 preflight/激活/提交能力判据；回执不确定只幂等补有证据的状态、快照、镜像和通知，不重新点击。
