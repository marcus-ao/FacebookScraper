# 审校台界面设计

本文记录 `web/ui/` 当前 React 界面的长期约束。接口、账本和发布边界以 [../DESIGN.md](../DESIGN.md) 为准；已拍板的功能取舍见 [DECISION_LOG.md](DECISION_LOG.md)。迁移期间使用的审计、基线和计划文件已移除，仍有效的结论已经收进这两份文件。

## 1. 使用场景

使用者是一名上海运营，日常目标是从待办中找到下一篇，核对英文来源、德语正文、图片、标签和链接，选择柏林时刻，再作出可追溯的单篇决定。界面是中文桌面工作台，信息密度高、动效少、错误原因明确。

设计性格固定为：克制、精确、紧凑、可信、可恢复、离线可用。

避免下列形态：

- 为装饰增加大面积渐变、纹理、插画或入场动画；
- 用多层卡片包住同一组内容；
- 只靠颜色表达状态；
- 让不可用按钮只显示灰色而不解释原因；
- 把系统路径、请求 ID、模型版本等实现细节放进日常业务流程；
- 用“已发布”表示 `scheduled`；
- 把未扫描、失败和零风险合并成一个安全状态。

## 2. 单一来源

| 内容 | 位置 |
|---|---|
| 设计 token、组件尺寸、断点 | `src/app/theme.ts` |

| 查询参数与旧链接转换 | `src/app/search-params.ts` |

组件样式可以定义布局，但不能另写一套颜色、字号、状态词或时区格式。业务状态不得由 CSS class、图标或颜色反推。

## 3. 布局与密度

顶部栏高 48px。页面标题与页面级动作共用一行；详情的吸顶摘要高 56px。正文与图片对照允许在各自区域内滚动，避免把整个详情页拉成长卷。

列表与历史使用 48px 行高。设计目标是：

| 分辨率 | 首屏可见行数 |
|---|---:|
| 1366×768 | 至少 12 行 |
| 1920×1080 | 至少 18 行 |

历史默认每页 50 条，可切换 20/50/100；分页控件在 1366×768 下仍应可达。当前缩略图服务成本可能使图片晚于文字出现，行布局不得等待图片再稳定。

在 1280–1599px 范围可以隐藏次要分类列，但来源平台、状态、问题指示和进入详情的动作必须保留。吸顶区不得折行覆盖内容。

间距只使用 4/8/12/16/24/32px 刻度。列表行不是卡片，只用分隔线。卡片只承载可以独立处理的对象，例如决策、图片对照、设置表单和运行状态分组；阴影只用于 Modal、Drawer、Dropdown、Popover 和 Tooltip。

## 4. 排版

普通界面使用系统字体：`Segoe UI`、`PingFang SC`、`Microsoft YaHei` 及平台回退，不加载网络字体。哈希、请求 ID 和模板内容才使用 `Cascadia Mono`、`Consolas` 等宽栈。

正文英德对照是唯一需要长时间逐字阅读的区域，固定 15px、1.7 行高。其它字号按 `theme.ts` 的七级刻度使用；同一层级必须同字号。每个页面有一个 `h1`，标题不能跳级。

## 5. 颜色

主色固定为 `#155EEF`。它对白色的对比度约 5.41:1，可用于含白字的主要按钮和焦点环。`#1677ff` 对白色约 4.10:1，不能替代该值。

中性色：

| token | 值 | 用途 |
|---|---|---|
| `bg` | `#f1f5f9` | 页面底 |
| `surface` | `#ffffff` | 表格、输入和独立卡片 |
| `surface-sunken` | `#f8fafc` | 表头、栏头、只读区 |
| `fg` | `#0f172a` | 正文 |
| `fg-muted` | `#475569` | 次要内容 |
| `border` | `#e2e8f0` | 分隔线 |
| `border-strong` | `#cbd5e1` | 输入框和按钮边界 |

内容区的高饱和语义色只有两组：

| 语义 | 前景 | 浅底 | 规则 |
|---|---|---|---|
| 确定性错误或硬闸 | `#dc2626` | `#fee2e2` | error 使用浅红底和深红实线；warn 使用浅红底和较浅实线 |
| 语义风险或需注意 | `#b45309` | `#fef3c7` | risk 使用黄褐色下划线，视觉重量低于错误 |
| 成功 | `#047857` | `#d1fae5` | 只用于状态，不使用满宽成功告警 |

标记重叠优先级保持 `error > risk > warn`；视觉重量保持 `error > warn > risk`。任何颜色状态还必须有文字或图标。

## 6. 状态与问题指示

业务七态加 `not_ready` 使用统一 12px Tag：

| 值 | 显示 | 处理方式 |
|---|---|---|
| `not_ready` | 未就绪 | 中性；系统尚未准备好，不属于当前待办 |
| `pending_review` | 待我审 | 主色浅底 |
| `edited` | 已修改 | 主色浅底 |
| `snoozed` | 已挂起 | 中性 |
| `approved` | 已通过 | 成功色；表示提交处理中 |
| `scheduled` | 已排期 | 成功色；只表示远端排期已确认 |
| `skipped` | 这篇不发 | 中性；正常业务终态，不用红色 |
| `handed_off` | 已交人工处理 | 中性终态 |

状态回答“处理到哪一步”，问题指示回答“这篇有什么需要注意”。列表单独显示硬闸、风险和第三方作者图标；红色只用于真正的错误或硬闸。终态行整体降饱和，`not_ready` 保持正常行底，因此两者仍可区分。

四个队列页签使用服务器返回的计数：待我审、未就绪、已挂起、已处理。筛选只影响当前表格，不在客户端重算服务端计数。

## 7. 按钮与表单

每个界面只有一个主要动作。付费动作保持普通按钮外观，在文案旁显示费用口径和剩余次数；它不能抢占保存或创建排期的主要层级。

破坏性动作只出现在“更多处理动作”菜单和确认对话框中。列表行不放重复的红色描边按钮。确认“不发”等动作时，确认按钮使用 danger 样式并要求理由。

任何 disabled 按钮都由 `DisabledReason` 或 `PaidActionButton` 提供可读原因。原因按最先可行动的阻塞项排序，避免一次罗列所有内部条件。

表单标签置顶。格式示例放 placeholder，业务含义变化才使用常驻说明。开发者注释和源码路径不能直接显示给运营；设置 API 返回的说明数据仍须保留，只在内容适合业务用户时进入 Tooltip。

进入德语编辑态时，输入区域、栏头和校验状态都应变化。保存中保持原按钮文案并显示 loading；保存成功用短暂 message 和状态 Tag；409 使用统一冲突恢复组件，允许载入最新来源并保留当前草稿。确定性检查用于辅助判断，不能因为金额等可人工解释的差异禁用保存。

## 8. 信息层级与告警

信息按三层放置：

| 层级 | 判据 | 载体 |
|---|---|---|
| 直接可见 | 不看会造成错误业务决定 | 页面、表格列、吸顶摘要 |
| 一次交互 | 有助于判断但不必持续占位 | Tooltip、Popover、折叠、标签页 |
| 二次交互 | 技术诊断、历史和低频详情 | Drawer 或独立页面 |

下列事实始终直接可见：缺德语图、源文已变化、落地页尚未确认、同渠道 90 分钟冲突。

满宽 Alert 只用于会造成明显业务后果且有下一步动作的情形：第三方来源待授权、组装告警、风险扫描失败或过期、冻结账号只读。`risk_scan.status === "not_scanned"` 使用中性状态；成功且零风险不显示成功告警。

## 9. 正文、链接和图片

英文与德语使用 1:1 Grid，各自独立滚动。确定性标记和风险标记保持分离；“下一处”使用立即滚动，因为嵌入式 Chromium 曾出现 smooth scroll 静默不动。

Facebook 正文插入动作在界面中显示人能理解的“链接 N”标记，保存请求使用 `{{linkN}}`。最终预览和字符数必须采用服务器替换真实 URL 后的结果。Instagram 不支持正文占位符，使用 bio CTA。

图片区逐张记录是否看过，切换任务时重置。缺德语图时明确显示正在回退原图；缩略图也要能直接识别缺图。图片可进入放大 Modal，Esc 关闭后焦点回到触发按钮。查看进度是提醒，不作为“通过”的硬闸。

## 10. 路由、状态和恢复

浏览器路径为 `/review`、`/history`、两类详情路径、`/calendar`、`/settings` 和 `/runtime`。队列上下文写入 `queue` 查询参数；历史页把 page、limit、platform、month、tag 等筛选写入 URL。详情返回路径包含来源列表和筛选上下文，刷新或分享后仍可恢复。

React Router 的 `location.state` 只能加速一次导航，不能作为唯一来源。导航选中项来自当前 route，不维护第二份状态。未知路径显示明确的找不到页面；旧查询链接由 `legacyRedirect` 转换。

正文和设置有统一离页保护，覆盖应用内导航、浏览器前进后退、刷新和关闭。对话框打开时捕获焦点，Esc 可关闭，关闭后焦点回到触发元素。

## 11. 动效与无障碍

动效强度保持低：颜色、边框和状态过渡 120–180ms；弹层使用组件默认动效；不做列表入场、页面切换、数字滚动或视差。`prefers-reduced-motion: reduce` 时把动画和过渡压到 0.01ms。

可访问性底线：

- 全局焦点环为 2px 主色、2px offset，不允许无替代地移除；
- 所有操作可通过键盘到达；
- Modal/Drawer 管理焦点，关闭后恢复；
- 正文与 12px 元信息对比度至少 4.5:1；
- 状态同时使用颜色和图标或文字；
- 错误动态区使用 `role="alert"`，状态动态区使用 `role="status"`；
- 页面语言是 `zh-CN`，Ant Design 和日期控件使用中文 locale；
- 页面始终只有一个 `h1`，标题层级不跳级。
