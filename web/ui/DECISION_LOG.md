# 审校台实现取舍

部署与命令见 [Web 使用说明](../README.md)，视觉规则见 [DESIGN.md](DESIGN.md)，业务与接口边界见 [接口契约](../DESIGN.md)。

| 选择 | 维护要求 |
|---|---|
| 保持现有技术栈 | TypeScript strict；直接导入的包须显式声明，已有组件或工具可满足时不引入同类依赖。浏览器测试使用 Python Playwright。 |
| URL 保存导航上下文 | 筛选、页码、当前任务和来源列表均可从 URL 恢复；`location.state` 只作辅助，保留 `?task=`、`?view=` 兼容。 |
| 服务端提供列表事实 | queue 是界面分组，status 是业务状态；计数与历史分页由服务端提供。列表只凭德语摘要判断有无译文，不猜机器或人工版本。 |
| 明确动作后刷新列表 | 进入详情和返回复用缓存；保存后更新行与计数，无法可靠推导时重取。运行状态从顶栏进入。 |
| 人工草稿独立 | 草稿保留在组件状态；产品分类与本地化分别保存、分别校验版本。localStorage 只存可丢失的界面偏好。 |
| 标签支持整段粘贴 | 解析为空格、逗号分隔的 chips，保留受保护标签并去重。 |
| 检查与人工决定分开 | 金额等可解释差异不禁用保存；结构问题阻止通过。图片查看进度只作提醒。 |
| 严格判定排期回执 | 仅 `ok === true && status === "scheduled"` 显示已排期；其他结果重读详情并提供核对入口。 |
| 服务层独立于 React | `services/` 与 `lib/` 不依赖 React；错误保留 status 和 payload，供建议时刻和月历回退使用。 |
| 类型对应实际响应 | 列表与详情分别建模；开发期浅层形状检查仅报告差异。契约变动同步类型、服务与隔离样本。 |

未提供后端契约的能力不显示空壳控件；待办及启动条件统一维护在 [REQUIREMENTS.md](../../docs/REQUIREMENTS.md)。
