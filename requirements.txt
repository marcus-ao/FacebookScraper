# G 组：排期时区。**这是 Windows 上的硬需求，不是便利品**（CR-60）。
# ⚠️ 同样违反「不引入新依赖」的约定，理由记在这里：
#
# 本机实测（2026-08-31）：`zoneinfo.TZPATH` 是**空的**，
# `ZoneInfo("Europe/Berlin")` 抛 `ZoneInfoNotFoundError` ——
# Windows 不自带 IANA 时区数据库，而 `zoneinfo` 只读系统数据库。
#
# 而 `PUBLISH_PLAN.md` 第 3.3 节把显式时区转换写成了**硬要求**：
# 「代码里显式做时区转换，不依赖本地时区隐式生效」，
# 并且要求**在夏令时切换日各测一次**（Europe/Berlin 每年切两次）。
# 那两件事都不可能靠固定 UTC 偏移做对 —— 一旦写死 +01:00/+02:00，
# 就会在切换日把帖子发到错误的时刻，而且**没人会立刻发现**。
#
# tzdata 是**纯数据包**（无原生代码、无传递依赖），这是所有可选方案里
# 侵入性最小的一个。
tzdata>=2024.1
